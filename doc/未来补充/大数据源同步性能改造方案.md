# 大数据源同步性能改造方案

> 状态：待实施 | 日期：2026-06-30 | 问题：数据源同步 10 万条记录耗时 ~50 分钟

---

## 一、问题诊断

当前数据源同步管线从 JDBC 拉取到向量入库，存在四个致命瓶颈。下文逐一剖析并给出精确到代码行的改造方案。

### 1.1 瓶颈全景

```
JdbcConnector             DataSyncEtlListener        BatchEmbeddingService      ChromaDB
┌──────────────┐         ┌─────────────────┐        ┌──────────────────┐      ┌──────────┐
│ SELECT *     │ ──全量──→│ for (record) {  │        │ BlockingQueue    │      │ .add()   │
│ 100K行       │  内存    │   insert(chunk) │──逐条─→│ capacity=2000    │─逐条─→│ × 100K  │
│ 无分页       │          │   insert(struct)│  提交  │ offer(5s超时)    │  写入 │ 次       │
│ 无流式       │          │   submit(embed) │        │                  │      │          │
└──────────────┘         └─────────────────┘        └──────────────────┘      └──────────┘
    3-5s                   600s (阻塞)                队列溢出/超时              2000s+
                                       ─────────────────────────────────────────────
                                       总计: ~50 分钟/10万条
```

### 1.2 四个致命伤

| # | 位置 | 问题 | 10 万条影响 |
|---|------|------|-----------|
| 1 | `JdbcConnector.fullSync()` | `SELECT *` 全量装进 `ArrayList`，无分页无流式 | 200MB 内存 + OOM 风险 |
| 2 | `DataSyncEtlListener` 第 98-161 行 | 逐条 `chunkMapper.insert()`，60 万次 SQL 往返 | ~600 秒阻塞 |
| 3 | `BatchEmbeddingService` 第 46 行 | `BlockingQueue(2000)`，`offer(5s timeout)` | 队列满后生产者阻塞 |
| 4 | `ChromaEmbeddingStore.add()` | 逐条 HTTP 写入 ChromaDB | ~2000 秒 |

## 二、改造方案

### 2.1 JDBC 连接器：全量拉取 → 流式分批

**文件**：`agent-qr-datasource/.../connector/JdbcConnector.java`

**当前代码问题**（第 110-125 行）：

```java
List<Map<String, Object>> allRows = new ArrayList<>();  // 全量装内存
while (rs.next()) {
    allRows.add(row);  // 100 万行 = OOM
}
```

**改造方案**：JDBC 流式读取 + 分批回调

```java
// 新增：分批全量同步（替代原 fullSync 方法中的全量加载逻辑）
private List<Map<String, Object>> fullSyncStreaming(SyncContext context) {
    Map<String, Object> config = context.getConfig();
    String url = (String) config.get("url");
    String username = (String) config.get("username");
    String password = (String) config.get("password");
    List<String> tableNames = (List<String>) config.get("tableNames");

    int fetchSize = getFetchSize(config);  // 默认 2000
    List<Map<String, Object>> allRows = new ArrayList<>();

    try (Connection conn = DriverManager.getConnection(url, username, password)) {
        conn.setAutoCommit(false);  // 流式读取必须关闭自动提交

        for (String table : tableNames) {
            String sql = buildSelectSql(table, config);
            try (PreparedStatement ps = conn.prepareStatement(sql,
                     ResultSet.TYPE_FORWARD_ONLY, ResultSet.CONCUR_READ_ONLY)) {
                ps.setFetchSize(Integer.MIN_VALUE);  // MySQL 流式读取标志
                // 或: ps.setFetchSize(fetchSize);   // 其他数据库用这个

                try (ResultSet rs = ps.executeQuery()) {
                    ResultSetMetaData meta = rs.getMetaData();
                    int colCount = meta.getColumnCount();
                    while (rs.next()) {
                        Map<String, Object> row = new LinkedHashMap<>();
                        for (int i = 1; i <= colCount; i++) {
                            row.put(meta.getColumnName(i), rs.getObject(i));
                        }
                        allRows.add(row);
                    }
                }
            }
        }
    } catch (SQLException e) {
        log.error("JDBC 流式全量同步失败", e);
        throw new BusinessException("JDBC 同步失败: " + e.getMessage());
    }
    return allRows;
}

private int getFetchSize(Map<String, Object> config) {
    Object fs = config.get("fetchSize");
    if (fs instanceof Number) {
        return ((Number) fs).intValue();
    }
    return 2000;  // 默认每批 2000 行
}
```

**效果**：100 万行内存占用从 ~2GB 降到 ~50MB（逐行读取，不在客户端积压 ResultSet）。

### 2.2 ETL 监听器：逐条 INSERT → 批量写入

**文件**：`agent-qr-knowledge/.../listener/DataSyncEtlListener.java`

**当前代码问题**（第 98-161 行）：

```java
for (int i = 0; i < records.size(); i++) {
    chunkMapper.insert(chunk);             // 逐条
    batchEmbeddingService.submit(chunk);   // 同步阻塞提交
    saveStructuredMetadata(chunkId, record); // 逐字段逐条
}
```

**改造方案**：三阶段分离：批量写 MySQL → 触发向量化事件 → 异步写 ChromaDB

```java
@Async("chunkExecutor")
@EventListener
public void handleDataQualityPassed(DataQualityPassedEvent event) {
    Long datasourceId = event.getDatasourceId();
    String batchId = event.getSyncBatchId();
    List<Map<String, Object>> passedData = event.getPassedData();

    if (passedData == null || passedData.isEmpty()) {
        return;
    }

    log.info("ETL 开始: datasourceId={}, batchId={}, records={}",
            datasourceId, batchId, passedData.size());

    try {
        DataSourceConfig config = dataSourceMapper.selectById(datasourceId);
        if (config == null) {
            deadLetterQueue.enqueue("ETL", datasourceId, "...", 
                new RuntimeException("数据源配置不存在"));
            return;
        }

        // ============ Phase 1: 标准化 + 批量写入 MySQL ============
        List<CanonicalRecord> records = dataNormalizer.normalize(passedData, config, batchId);
        List<Chunk> chunks = buildChunks(records, datasourceId, passedData);
        List<ChunkStructured> structuredList = buildStructuredMetadata(records);

        // 批量写入 kb_chunk（1000 条/批）
        batchInsertChunks(chunks);
        // 批量写入 kb_chunk_structured（1000 条/批）
        batchInsertStructured(structuredList);

        log.info("ETL MySQL 写入完成: datasourceId={}, chunks={}, structured={}",
                datasourceId, chunks.size(), structuredList.size());

        // ============ Phase 2: 发布事件 → 异步向量化 ============
        eventPublisher.publishEvent(new ChunksBatchCreatedEvent(
                this, datasourceId, batchId,
                chunks.stream().map(Chunk::getId).toList()));

    } catch (Exception e) {
        log.error("ETL 失败: datasourceId={}", datasourceId, e);
        deadLetterQueue.enqueue("ETL", datasourceId, "...", e);
    }
}

// ── 批量写入工具方法 ──

/** 每批最多 1000 条 */
private static final int BATCH_SIZE = 1000;

private void batchInsertChunks(List<Chunk> chunks) {
    for (int i = 0; i < chunks.size(); i += BATCH_SIZE) {
        int end = Math.min(i + BATCH_SIZE, chunks.size());
        chunkMapper.insertBatch(chunks.subList(i, end));
    }
}

private void batchInsertStructured(List<ChunkStructured> list) {
    for (int i = 0; i < list.size(); i += BATCH_SIZE) {
        int end = Math.min(i + BATCH_SIZE, list.size());
        chunkStructuredMapper.insertBatch(list.subList(i, end));
    }
}

/** 标准化记录 → Chunk 实体列表（仅构造，不写入） */
private List<Chunk> buildChunks(List<CanonicalRecord> records, 
        Long datasourceId, List<Map<String, Object>> passedData) {
    List<Chunk> chunks = new ArrayList<>(records.size());
    for (int i = 0; i < records.size(); i++) {
        CanonicalRecord record = records.get(i);
        Chunk chunk = new Chunk();
        chunk.setDocumentId(null);
        chunk.setDatasourceId(datasourceId);
        chunk.setChunkIndex(i);
        chunk.setContent(record.getCanonicalText());
        chunk.setCharCount(record.getCanonicalText() != null 
                ? record.getCanonicalText().length() : 0);
        chunk.setChromaId("pending");
        chunk.setDeleted(0);
        chunk.setStatus("READY");
        if (i < passedData.size()) {
            chunk.setRecordHash(
                    FingerprintUtils.computeRecordFingerprint(passedData.get(i)));
        }
        chunks.add(chunk);
    }
    return chunks;
}

/** 标准化记录 → ChunkStructured 列表（仅构造，不写入） */
private List<ChunkStructured> buildStructuredMetadata(List<CanonicalRecord> records) {
    List<ChunkStructured> result = new ArrayList<>();
    for (CanonicalRecord record : records) {
        Map<String, Object> metadata = record.getMetadata();
        if (metadata == null || metadata.isEmpty()) continue;

        // 注意：此时 chunk 尚未插入，ID 未知
        // 需要在批量插入后，用 chunk.getId() 回填
        // 或者先插入 chunk → 获取 ID → 再构造 structured 并插入
        for (Map.Entry<String, Object> entry : metadata.entrySet()) {
            if (entry.getValue() == null) continue;
            ChunkStructured cs = buildStructuredField(
                    null, // chunkId 稍后回填
                    record.getDomain(), entry.getKey(), entry.getValue());
            result.add(cs);
        }
    }
    return result;
}
```

**关键的 ID 回填问题**：上面的 `buildStructuredMetadata()` 在 chunk 插入前构造，chunkId 未知。实际实施时需要两阶段：

```java
// Phase 1a: 批量插入 chunk → MyBatis-Plus 自动回填 ID
chunkMapper.insertBatch(chunks);  // 每条 chunk.getId() 被填充

// Phase 1b: 用已知的 chunkId 构造 structured 并批量插入
List<ChunkStructured> structuredList = new ArrayList<>();
for (int i = 0; i < records.size(); i++) {
    Long chunkId = chunks.get(i).getId();  // 已回填
    CanonicalRecord record = records.get(i);
    for (Map.Entry<String, Object> entry : record.getMetadata().entrySet()) {
        structuredList.add(buildStructuredField(chunkId, record.getDomain(), 
                entry.getKey(), entry.getValue()));
    }
}
batchInsertStructured(structuredList);
```

### 2.5 向量化队列：解除阻塞

**文件**：`agent-qr-rag/.../embedding/BatchEmbeddingService.java`

**当前问题**：`BlockingQueue(2000)` + `offer(5s timeout)` → ETL 生产者阻塞。

**改造方案**：增加队列容量 + 非阻塞提交 + 背压监控

```java
// 第 46 行改前
private final BlockingQueue<EmbedTask> taskQueue = new LinkedBlockingQueue<>(2000);

// 改后：按 CPU 核心数 × batchSize 计算合理容量，确保高峰期不阻塞
// 8 cores × 32 × 10 = 2560，取 10000 留足余量
@Value("${agent-qr.embedding.queue-capacity:10000}")
private int queueCapacity;
private final BlockingQueue<EmbedTask> taskQueue;

public BatchEmbeddingService() {
    this.taskQueue = new LinkedBlockingQueue<>(queueCapacity);
}

// 第 81-88 行改：非阻塞提交 + 降级
public CompletableFuture<float[]> submit(EmbeddableText text) {
    CompletableFuture<float[]> future = new CompletableFuture<>();
    EmbedTask task = new EmbedTask(text, future);

    // 先尝试非阻塞 offer
    if (!taskQueue.offer(task)) {
        // 队列满 → 同步执行，不阻塞调用方
        log.warn("向量化队列已满({})，降级同步执行: textId={}", 
                queueCapacity, text.getId());
        try {
            EmbeddingProvider provider = providerFactory.getEmbeddingProvider();
            float[] vector = provider.embed(text.getContent());
            future.complete(vector);
        } catch (Exception e) {
            future.completeExceptionally(e);
        }
    }
    return future;
}
```

**更好的架构**：将向量化触发从同步 `submit()` 改为事件驱动。新增 `ChunksBatchCreatedEvent` 事件，由独立的 `ChunkEmbeddingBatchListener` 消费，从 MySQL 分批读取 chunk → 提交向量化 → 写 ChromaDB。这样 ETL 写入和向量化完全解耦。

### 2.6 ChromaDB：逐条 add → 批量 addAll

**文件**：新建 `ChunkEmbeddingBatchListener.java`（替代原有的回调模式）

```java
/**
 * 切片批量向量化监听器（P4 改造）。
 * 监听 ChunksBatchCreatedEvent，批量读取 chunk → 批量向量化 → 批量写 ChromaDB。
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class ChunkEmbeddingBatchListener {

    private final ChunkMapper chunkMapper;
    private final BatchEmbeddingService batchEmbeddingService;
    private final ChromaEmbeddingStore chromaEmbeddingStore;
    private final DeadLetterQueue deadLetterQueue;

    private static final int EMBED_BATCH = 100;
    private static final int CHROMA_BATCH = 32;

    @Async("embeddingBatchExecutor")
    @EventListener
    public void handleChunksBatchCreated(ChunksBatchCreatedEvent event) {
        List<Long> chunkIds = event.getChunkIds();
        log.info("开始批量向量化: datasourceId={}, chunkCount={}", 
                event.getDatasourceId(), chunkIds.size());

        for (int i = 0; i < chunkIds.size(); i += EMBED_BATCH) {
            int end = Math.min(i + EMBED_BATCH, chunkIds.size());
            List<Long> batch = chunkIds.subList(i, end);

            // 1. 从 MySQL 读取切片内容
            List<Chunk> chunks = chunkMapper.selectBatchIds(batch);

            // 2. 提取文本
            List<String> texts = chunks.stream()
                    .map(Chunk::getContent)
                    .toList();

            // 3. 批量向量化
            List<float[]> vectors;
            try {
                vectors = batchEmbeddingService.embedBatchSync(texts);
            } catch (Exception e) {
                deadLetterQueue.enqueue("EMBED", event.getDatasourceId(), 
                        "...", e);
                continue;
            }

            // 4. 批量写 ChromaDB — 每批 CHROMA_BATCH 条
            for (int j = 0; j < chunks.size(); j += CHROMA_BATCH) {
                int subEnd = Math.min(j + CHROMA_BATCH, chunks.size());
                List<Embedding> embBatch = new ArrayList<>();
                List<TextSegment> segBatch = new ArrayList<>();
                List<Chunk> chunkBatch = chunks.subList(j, subEnd);

                for (int k = j; k < subEnd; k++) {
                    embBatch.add(new Embedding(vectors.get(k)));
                    segBatch.add(TextSegment.from(chunks.get(k).getContent(), 
                            new Metadata(Map.of(
                                "chunk_id", chunks.get(k).getId().toString(),
                                "datasource_id", event.getDatasourceId().toString()))));
                }

                try {
                    chromaEmbeddingStore.addAll(embBatch, segBatch);
                    // 更新 chromaId
                    for (Chunk c : chunkBatch) {
                        c.setChromaId("batch-" + event.getBatchId() + "-" + c.getId());
                        chunkMapper.updateById(c);
                    }
                } catch (Exception e) {
                    deadLetterQueue.enqueue("CHROMA_WRITE", event.getDatasourceId(), 
                            "...", e);
                }
            }
        }
        log.info("批量向量化完成: datasourceId={}", event.getDatasourceId());
    }
}
```

### 2.7 BM25 索引：全量重建 → 增量更新

**文件**：`agent-qr-rag/.../retriever/BM25Retriever.java`

```java
// BM25Retriever 新增批量添加方法（已有个别 addToIndex，扩展为批量）
public void addBatchToIndex(List<Chunk> chunks) {
    try {
        IndexWriterConfig config = new IndexWriterConfig(analyzer);

        log.error("BM25 索引批量添加失败", e);
    }
```

## 四、改造前后对比

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| JDBC 读取（10万行） | 全量装内存，200MB | 流式逐行读取，~50MB |
| MySQL 写入（10万条） | 逐条 60万次 SQL，~600s | 批量 600 次 SQL，~10s |
| 向量化提交 | 阻塞 `offer(5s)`，队列容量 2000 | 事件驱动异步，非阻塞 |
| ChromaDB 写入 | 逐条 `add()` × 100K | `addAll()` 分批，~300s |
| BM25 索引更新 | 下次重启全量重建 | 增量更新，~5s |
| **总耗时（10万条）** | **~50 分钟** | **~6-8 分钟（同步完成）+ ~5 分钟（后台向量化）** |
| 同步完成即可检索 | ❌ 需等 ChromaDB 写完 | ✅ BM25 立即可用 |

### 6.2 压力测试

```
1. 创建 JDBC 数据源，指向测试表
2. 触发全量同步
3. 监控指标:
   - ETL 阶段耗时（到 MySQL 写入完成为止）
```
