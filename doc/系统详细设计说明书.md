### 2.2 统一响应类 Result

```java
/**
 * 统一 API 响应结果封装
 * @param <T> 响应数据类型
 */
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Result<T> {

    /** 状态码 */
    private Integer code;

    /** 提示信息 */
    private String message;

    /** 响应数据 */
    private T data;

    /** 时间戳 */
    private Long timestamp;

    /**
     * 成功响应（无数据）
     */
    public static <T> Result<T> success() {
        return new Result<>(200, "操作成功", null, System.currentTimeMillis());
    }

    /**
     * 成功响应（带数据）
     * @param data 响应数据
     */
    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data, System.currentTimeMillis());
    }

    /**
     * 成功响应（自定义消息）
     * @param message 提示信息
     * @param data 响应数据
     */
    public static <T> Result<T> success(String message, T data) {
        return new Result<>(200, message, data, System.currentTimeMillis());
    }

    /**
     * 失败响应
     * @param code 错误码
     * @param message 错误信息
     */
    public static <T> Result<T> error(Integer code, String message) {
        return new Result<>(code, message, null, System.currentTimeMillis());
    }
}
```

### 2.3 全局异常处理 GlobalExceptionHandler

```java
/**
 * 全局异常处理器
 * 统一处理 Controller 层抛出的异常，返回标准 JSON 响应
 */
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    /**
     * 处理业务异常
     */
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    /**
     * 处理参数校验异常
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining(", "));
        return Result.error(400, msg);
    }

    /**
     * 处理访问拒绝异常（权限不足）
     */
    @ExceptionHandler(AccessDeniedException.class)
    public Result<Void> handleAccessDeniedException(AccessDeniedException e) {
        return Result.error(403, "权限不足，无法访问该资源");
    }

    /**
     * 处理未知异常
     */
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "服务器内部错误，请稍后重试");
    }
}
```

| ---------------- | -------------------------------------- | ---------------------------------------- | ------------------------- |
| `login`          | `LoginDTO(username, password)`         | `LoginVO(accessToken, refreshToken, expiresIn, userId, username, role, department, clearanceLevel, allowedDomains, title)` | BCrypt 验证密码后生成双Token（含ABAC属性） |

**登录流程**：

```
1. 根据 username 查询 sys_user
2. 用户不存在 → 抛出 BusinessException("用户名或密码错误")
3. 用户 status=0 → 抛出 BusinessException("账号已被禁用")
4. BCrypt.matches(password, dbPassword) 验证密码
5. 不匹配 → 抛出 BusinessException("用户名或密码错误")
6. 签发双 Token：Access Token（含 ABAC 属性：userId/role/department/clearanceLevel/allowedDomains/title，有效期 30min）+ Refresh Token（有效期 7day）
7. 返回 LoginVO（含双 Token + 用户基本信息 + ABAC 属性）
```

#### 3.2.3 PasswordUtil（BCrypt 密码工具） `[P1]`

```java
/**
 * BCrypt 密码加密验证工具类
 * 使用 BCrypt 自适应哈希算法替代不安全的 MD5
 * strength=12 提供约 2^12 轮迭代，有效抵御 GPU 暴力破解和彩虹表攻击
 */
@Component
public class PasswordUtil {

    private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(12);

    /**
     * 对明文密码进行 BCrypt 加密
     * @param rawPassword 明文密码
     * @return BCrypt 密文（60 字符，含自动生成的随机盐）
     */
    public String encode(String rawPassword) {
        return encoder.encode(rawPassword);
    }

    /**
     * 验证明文密码与 BCrypt 密文是否匹配
     * @param rawPassword 明文密码
     * @param encodedPassword BCrypt 密文
     * @return 是否匹配
     */
    public boolean matches(String rawPassword, String encodedPassword) {
        return encoder.matches(rawPassword, encodedPassword);
    }
}
```

#### 3.2.4 JwtUtil `[P1]`

```java
/**
 * JWT 令牌工具类
 */
@Component
public class JwtUtil {

    @Value("${jwt.secret}")
    private String secret;

    @Value("${jwt.expiration:86400000}")
    private Long expiration; // 默认24小时

    /**
     * 生成 JWT 令牌
     * @param userId 用户ID
     * @param username 用户名
     * @param role 角色
     * @return JWT 字符串
     */
    public String generateToken(Long userId, String username, String role) {
        Date now = new Date();
        Date expiryDate = new Date(now.getTime() + expiration);
        return Jwts.builder()
                .setSubject(username)
                .claim("userId", userId)
                .claim("role", role)
                .setIssuedAt(now)
                .setExpiration(expiryDate)
                .signWith(SignatureAlgorithm.HS256, secret)
                .compact();
    }

    /**
     * 从令牌中解析用户名
     * @param token JWT 令牌
     * @return 用户名
     */
    public String getUsernameFromToken(String token) {
        return getClaimsFromToken(token).getSubject();
    }

    /**
     * 验证令牌是否有效
     * @param token JWT 令牌
     * @return 是否有效
     */
    public boolean validateToken(String token) {
        try {
            getClaimsFromToken(token);
            return true;
        } catch (Exception e) {
            return false;
        }
    }

    /**
     * 解析令牌 Claims
     */
    private Claims getClaimsFromToken(String token) {
        return Jwts.parser()
                .setSigningKey(secret)
                .parseClaimsJws(token)
                .getBody();
    }
}
```

#### 3.2.5 JwtAuthenticationFilter `[P1]`

```java
/**
 * JWT 认证过滤器
 * 在 Spring Security 过滤器链中拦截请求，解析 JWT 并注入 SecurityContext
 */
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Autowired
    private JwtUtil jwtUtil;

    @Autowired
    private SysUserMapper sysUserMapper;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain filterChain)
            throws ServletException, IOException {

        // 1. 从请求头获取 Token
        String token = extractToken(request);
        if (token == null) {
            filterChain.doFilter(request, response);
            return;
        }

        // 2. 验证 Token 有效性
        if (!jwtUtil.validateToken(token)) {
            filterChain.doFilter(request, response);
            return;
        }

        // 3. 解析用户名，查询用户
        String username = jwtUtil.getUsernameFromToken(token);
        SysUser user = sysUserMapper.selectByUsername(username);
        if (user == null) {
            filterChain.doFilter(request, response);
            return;
        }

        // 4. 构建认证对象，注入 SecurityContext
        UsernamePasswordAuthenticationToken authentication =
                new UsernamePasswordAuthenticationToken(
                        user, null,
                        List.of(new SimpleGrantedAuthority("ROLE_" + user.getRole().toUpperCase()))
                );
        SecurityContextHolder.getContext().setAuthentication(authentication);

        filterChain.doFilter(request, response);
    }

    /**
     * 从 Authorization 头中提取 Bearer Token
     */
    private String extractToken(HttpServletRequest request) {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            return header.substring(7);
        }
        return null;
    }
}
```

#### 3.2.8 UserPrincipal（ABAC 扩展用户主体） `[P2]`

```java
/**
 * ★ ABAC 扩展用户主体
 * 从 JWT Payload 中解析 ABAC 属性，注入 SecurityContext
 * 替代原有的简单角色判断，支持部门/密级/域/职级多维度属性
 */
@Data
public class UserPrincipal {

    private Long userId;
    private String username;
    private String role;
    /** ★ 所属部门 */
    private String department;
    /** ★ 数据密级等级 */
    private Integer clearanceLevel;
    /** ★ 允许访问的业务域列表 */
    private List<String> allowedDomains;
    /** ★ 职级 */
    private String title;

    // 从 JWT Claims 构建
    public static UserPrincipal fromClaims(Claims claims) {
        UserPrincipal user = new UserPrincipal();
        user.setUserId(claims.get("userId", Long.class));
        user.setUsername(claims.getSubject());
        user.setRole(claims.get("role", String.class));
        user.setDepartment(claims.get("department", String.class));
        user.setClearanceLevel(claims.get("clearanceLevel", Integer.class));
        // allowedDomains 在 JWT 中存为逗号分隔字符串
        String domains = claims.get("allowedDomains", String.class);
        user.setAllowedDomains(domains != null
            ? Arrays.asList(domains.split(","))
            : Collections.emptyList());
        user.setTitle(claims.get("title", String.class));
        return user;
    }

    /** 是否为管理员（绕过 ABAC 属性检查） */
    public boolean isAdmin() {
        return "admin".equals(this.role);
    }

    /** 是否有权访问指定业务域 */
    public boolean hasDomainAccess(String domain) {
        if (domain == null) return true;
        return this.allowedDomains.contains(domain)
            || domain.equals(this.department);
    }

    /** 密级是否足够访问指定资源 */
    public boolean hasClearance(int resourceLevel) {
        return this.clearanceLevel >= resourceLevel;
    }
}
```

#### 3.2.9 AbacEvaluator（ABAC 属性策略评估器） `[P2]`

```java
/**
 * ★ ABAC 属性访问控制评估器
 * 所有权限策略集中在此类中，通过 SpEL @PreAuthorize 表达式调用
 *
 * 设计原则：
 * 1. Admin 全权限（绕过所有属性检查）
 * 2. 默认拒绝（方法返回值只有 true/false，无匹配规则时返回 false）
 * 3. 策略集中（所有规则在一个类中，便于审计和维护）
 * 4. 延迟 < 1ms（纯内存属性比较，无外部调用）
 */
@Component("abac")
@Slf4j
public class AbacEvaluator {

    @Autowired
    private DocumentMapper documentMapper;

    // ==================== 域权限 ====================

    /**
     * 用户能否在指定域内执行查询操作
     * 规则：
     *   1. admin → 允许
     *   2. user.allowedDomains 包含 domain → 允许
     *   3. user.department == domain → 允许
     *   4. 其他 → 拒绝
     *
     * 使用方式: @PreAuthorize("@abac.canQueryDomain(principal, #domain)")
     */
    public boolean canQueryDomain(UserPrincipal user, String domain) {
        if (user.isAdmin()) return true;
        if (domain == null) return true; // 未指定域，不限制

        boolean allowed = user.hasDomainAccess(domain);
        if (!allowed) {
            log.warn("ABAC 拒绝: 用户 {} (部门={}) 无法访问 {} 域",
                user.getUsername(), user.getDepartment(), domain);
        }
        return allowed;
    }

    // ==================== 文档权限 ====================

    /**
     * 用户能否访问指定文档
     * 规则：
     *   1. admin → 允许
     *   2. 用户密级 >= 文档密级 AND 用户有文档域的权限
     *   3. 其他 → 拒绝
     *
     * 使用方式: @PreAuthorize("@abac.canAccessDocument(principal, #documentId)")
     */
    public boolean canAccessDocument(UserPrincipal user, Long documentId) {
        if (user.isAdmin()) return true;

        Document doc = documentMapper.selectById(documentId);
        if (doc == null) return false;

        // ★ 密级检查
        if (!user.hasClearance(doc.getSensitivityLevel())) {
            log.warn("ABAC 拒绝: 用户 {} 密级 {} 无法访问密级 {} 的文档 {}",
                user.getUsername(), user.getClearanceLevel(),
                doc.getSensitivityLevel(), documentId);
            return false;
        }

        // ★ 域检查
        return canQueryDomain(user, doc.getDomain());
    }

    /**
     * 用户能否上传文档到指定域
     * 额外要求：职级 ≥ manager
     *
     * 使用方式: @PreAuthorize("@abac.canUploadToDomain(principal, #domain)")
     */
    public boolean canUploadToDomain(UserPrincipal user, String domain) {
        if (user.isAdmin()) return true;
        if (!canQueryDomain(user, domain)) return false;

        boolean isManager = "manager".equals(user.getTitle())
                         || "director".equals(user.getTitle());
        if (!isManager) {
            log.warn("ABAC 拒绝: 用户 {} 职级 {} 无法上传文档 (需要 manager+)",
                user.getUsername(), user.getTitle());
        }
        return isManager;
    }

    /**
     * 用户能否删除指定文档
     * 额外要求：职级 == director
     */
    public boolean canDeleteDocument(UserPrincipal user, Long documentId) {
        if (user.isAdmin()) return true;
        if (!canAccessDocument(user, documentId)) return false;

        boolean isDirector = "director".equals(user.getTitle());
        if (!isDirector) {
            log.warn("ABAC 拒绝: 用户 {} 职级 {} 无法删除文档 (需要 director)",
                user.getUsername(), user.getTitle());
        }
        return isDirector;
    }

    // ==================== 用户管理权限 ====================

    /**
     * 用户能否修改用户信息
     * admin → 允许所有；普通用户 → 只能改自己的非敏感字段
     */
    public boolean canModifyUser(UserPrincipal user, Long targetUserId) {
        if (user.isAdmin()) return true;
        if (user.getUserId().equals(targetUserId)) return true;
        log.warn("ABAC 拒绝: 用户 {} 无法修改用户 {} 的信息",
            user.getUsername(), targetUserId);
        return false;
    }

    // ==================== 数据源管理 ====================

    /**
     * 只有 admin 可以管理数据源
     */
    public boolean canManageDatasource(UserPrincipal user) {
        return user.isAdmin();
    }
}
```

```java
/**
 * JWT 工具类 v2 —— 支持 ABAC 属性

@Component
public class JwtUtil {

    @Value("${jwt.secret}") private String secret;
    @Value("${jwt.access-expiration:1800}") private Long accessExpiration;     // 30min
    @Value("${jwt.refresh-expiration:604800}") private Long refreshExpiration; // 7day

    /**
     * 生成 Access Token（含 ABAC 属性）
     */
    public String generateAccessToken(SysUser user) {
        Date now = new Date();
        return Jwts.builder()
            .setSubject(user.getUsername())
            .claim("userId", user.getId())
            .claim("role", user.getRole())
            .claim("department", user.getDepartment())         // ★ ABAC
            .claim("clearanceLevel", user.getClearanceLevel()) // ★ ABAC
            .claim("allowedDomains", user.getAllowedDomains()) // ★ ABAC
            .claim("title", user.getTitle())                   // ★ ABAC
            .setIssuedAt(now)
            .setExpiration(new Date(now.getTime() + accessExpiration * 1000))
            .signWith(SignatureAlgorithm.HS256, secret)
            .compact();
    }

    /**
     * 生成 Refresh Token（不含 ABAC 属性，仅用于刷新）
     */
    public String generateRefreshToken(SysUser user) {
        Date now = new Date();
        return Jwts.builder()
            .setSubject(user.getUsername())
            .claim("userId", user.getId())
            .claim("tokenType", "refresh")
            .setIssuedAt(now)
            .setExpiration(new Date(now.getTime() + refreshExpiration * 1000))
            .signWith(SignatureAlgorithm.HS256, secret)
            .compact();
    }

    /** 从 Token 解析 ABAC 用户主体 */
    public UserPrincipal parseUserPrincipal(String token) {
        Claims claims = getClaimsFromToken(token);
        return UserPrincipal.fromClaims(claims);
    }
```

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Autowired private JwtUtil jwtUtil;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain chain)
            throws ServletException, IOException {

        String token = extractToken(request);
        if (token == null || !jwtUtil.validateToken(token)) {
            chain.doFilter(request, response);
            return;
        }

        // ★ 解析 ABAC 扩展用户主体
        UserPrincipal user = jwtUtil.parseUserPrincipal(token);

        // ★ 构建包含 ABAC 属性的认证对象
        List<GrantedAuthority> authorities = new ArrayList<>();
        authorities.add(new SimpleGrantedAuthority("ROLE_" + user.getRole().toUpperCase()));
        // 将 ABAC 属性也编码为 GrantedAuthority（可选，用于 hasAuthority 匹配）
        user.getAllowedDomains().forEach(d ->
            authorities.add(new SimpleGrantedAuthority("DOMAIN_" + d)));

        UsernamePasswordAuthenticationToken authentication =
            new UsernamePasswordAuthenticationToken(user, null, authorities);
        SecurityContextHolder.getContext().setAuthentication(authentication);

        chain.doFilter(request, response);
    }
}
```

```java
/**

 * 替代 Spring Security 默认的 403 空白页，返回结构化 JSON

@RestControllerAdvice
public class AbacAccessDeniedHandler {

    /**
     * 处理 @PreAuthorize 拒绝
     */
    @ExceptionHandler(AccessDeniedException.class)
    public ResponseEntity<Result<Void>> handleAccessDenied(AccessDeniedException e,
                                                            HttpServletRequest request) {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        UserPrincipal user = (auth != null && auth.getPrincipal() instanceof UserPrincipal)
            ? (UserPrincipal) auth.getPrincipal() : null;

        String username = user != null ? user.getUsername() : "anonymous";
        String traceId = MDC.get("traceId");

        // ★ 结构化审计日志

        auditLog.put("department", user != null ? user.getDepartment() : "N/A");
        auditLog.put("uri", request.getRequestURI());
        auditLog.put("method", request.getMethod());
        auditLog.put("traceId", traceId);
        auditLog.put("timestamp", LocalDateTime.now().toString());
        auditLog.put("reason", e.getMessage());

        log.warn("ABAC 权限拒绝: {}", JSON.toJSONString(auditLog));

        Result<Void> result = Result.error(403,
            String.format("权限不足: %s", e.getMessage()));
```

```java
/**
 * 文档命令服务（写操作）
 * 处理文档上传、删除等写操作，上传后发布事件触发异步处理链
 */
@Service
@Slf4j
public class DocumentCommandService {

    @Autowired
    private DocumentMapper documentMapper;
    @Autowired
    private ChunkMapper chunkMapper;
    @Autowired
    private FileStorageService fileStorageService;
    @Autowired
    private ApplicationEventPublisher eventPublisher;

    /** 允许的文件类型 */
    private static final Set<String> ALLOWED_TYPES =
            Set.of("pdf", "docx", "txt", "md");

    /** 文件大小上限 */
    private static final long MAX_FILE_SIZE = 50 * 1024 * 1024; // 50MB

    /**
     * 上传文档（同步保存文件+创建记录，异步处理内容）
     * @param file 上传的文件
     * @param title 文档标题（可选）
     * @param userId 上传用户ID
     * @return 创建的文档记录
     */
    @Transactional
    public Document uploadDocument(MultipartFile file, String title, Long userId) {
        // 1. 校验文件类型
        String fileType = getFileExtension(file.getOriginalFilename());
        if (!ALLOWED_TYPES.contains(fileType)) {
            throw new BusinessException("不支持的文件格式，仅支持: pdf, docx, txt, md");
        }

        // 2. 校验文件大小
        if (file.getSize() > MAX_FILE_SIZE) {
            throw new BusinessException("文件大小不能超过 50MB");
        }

        // 3. 保存文件到服务器
        String filePath = fileStorageService.store(file);

        // 4. 创建文档记录
        Document doc = new Document();
        doc.setTitle(title != null ? title : file.getOriginalFilename());
        doc.setFileName(file.getOriginalFilename());
        doc.setFilePath(filePath);
        doc.setFileType(fileType);
        doc.setFileSize(file.getSize());
        doc.setStatus(DocumentStatus.UPLOADED.name());
        doc.setUploadUserId(userId);
        documentMapper.insert(doc);

        // 5. 发布文档上传事件（触发异步处理链）
        DocumentUploadedEvent event = new DocumentUploadedEvent();
        event.setDocumentId(doc.getId());
        event.setFilePath(filePath);
        event.setFileName(file.getOriginalFilename());
        event.setFileType(fileType);
        event.setUserId(userId);
        eventPublisher.publishEvent(event);

        log.info("文档上传成功: id={}, name={}", doc.getId(), doc.getFileName());
        return doc; // 立即返回，后续异步处理
    }

    /**
     * [P1] 删除文档及其关联数据（直接删除，P2 阶段废弃）
     * @deprecated P2 阶段由 {@link #requestDeleteDocument(Long)} 替代，
     *             采用事件驱动软删除策略，由 compensation 模块异步物理删除
     * @param documentId 文档ID
     */
    @Transactional
    @Deprecated
    public void deleteDocument(Long documentId) {
        Document doc = documentMapper.selectById(documentId);
        if (doc == null) {
            throw new BusinessException(404, "文档不存在");
        }

        // 1. 删除服务器文件
        fileStorageService.delete(doc.getFilePath());

        // 2. 删除切片记录
        chunkMapper.deleteByDocumentId(documentId);

        // 3. 删除 ChromaDB 向量（通过 chroma_id）
        chromaVectorStore.deleteByDocumentId(documentId);

        // 4. 删除文档记录
        documentMapper.deleteById(documentId);
        log.info("文档删除成功: id={}", documentId);
    }

    /**
     * ★ [P2] 事件驱动的软删除请求
     * 采用"先标记后清理"策略：标记 DELETING → 收集切片信息 → 发布事件 → 立即返回
     *
     * 关键设计：
     * 1. knowledge 模块只发布事件，不注入 compensation 的任何类 → 无循环依赖
     * 2. compensation 模块的 DocumentDeleteListener 通过 @TransactionalEventListener 接收事件
     * 3. 用户在 Controller 调用后立即得到 200 响应，物理删除在后台异步完成
     *
     * @param documentId 文档ID
     */
    @Transactional
    public void requestDeleteDocument(Long documentId) {
        Document doc = documentMapper.selectById(documentId);
        if (doc == null) {
            throw new BusinessException(404, "文档不存在");
        }
        if ("DELETING".equals(doc.getStatus())) {
            throw new BusinessException("文档正在删除中，请稍后重试");
        }

        // 1. 标记文档状态为 DELETING（防止并发删除）
        documentMapper.updateStatus(documentId, DocumentStatus.DELETING.name());

        // 2. 收集切片列表和 ChromaDB 向量 ID
        List<Chunk> chunks = chunkMapper.selectByDocumentId(documentId);
        List<String> chromaIds = chunkMapper.selectChromaIdsByDocumentId(documentId);

        // 3. ★ 发布 DocumentDeleteRequestedEvent 事件（定义在 agent-qr-common，无循环依赖）
        DocumentDeleteRequestedEvent event = new DocumentDeleteRequestedEvent();
        event.setDocumentId(documentId);
        event.setChunkIds(chunks.stream().map(Chunk::getId).collect(Collectors.toList()));
        event.setChromaIds(chromaIds);
        event.setFilePath(doc.getFilePath());
        eventPublisher.publishEvent(event);

        // 4. ★ 立即返回，不等待物理删除完成
        //    compensation 模块的 DocumentDeleteListener 在事务提交后异步执行：
        //    → MySQL 逻辑删除（chunkMapper.softDeleteByDocumentId + documentMapper.softDelete）
        //    → ChromaDB 物理删除（DocumentDeleteServiceV2.asyncPhysicalDelete）
        log.info("文档删除请求已发布: id={}, chromaIds={}", documentId, chromaIds.size());
    }

    /**
     * 获取文件扩展名
     */
    private String getFileExtension(String fileName) {
        if (fileName == null) return "";
        int dotIndex = fileName.lastIndexOf('.');
        return dotIndex == -1 ? "" : fileName.substring(dotIndex + 1).toLowerCase();
    }
}
```

```java
             XWPFDocument document = new XWPFDocument(fis)) {
            StringBuilder sb = new StringBuilder();

            // 遍历所有元素（段落 + 表格）
            for (IBodyElement element : document.getBodyElements()) {
                if (element instanceof XWPFParagraph) {
                    sb.append(((XWPFParagraph) element).getText()).append("\n");
                } else if (element instanceof XWPFTable) {
                    // ★ 将表格转为 Markdown 格式
                    sb.append(tableToMarkdown((XWPFTable) element)).append("\n\n");
                }
            }
            return sb.toString();
        } catch (IOException e) {
            throw new BusinessException("DOCX 解析失败: " + e.getMessage());
        }
    }

    /** 将 XWPFTable 转为 Markdown 表格 */
    private String tableToMarkdown(XWPFTable table) {
        StringBuilder md = new StringBuilder();
        List<XWPFTableRow> rows = table.getRows();
        for (int i = 0; i < rows.size(); i++) {
            md.append("|");
            for (XWPFTableCell cell : rows.get(i).getTableCells()) {
                md.append(" ").append(cell.getText().replace("\n", " ")).append(" |");
            }
            md.append("\n");
            // 表头分隔线
            if (i == 0) {
                md.append("|");
                for (int j = 0; j < rows.get(i).getTableCells().size(); j++) {
                    md.append(" --- |");
                }
                md.append("\n");
            }
        }
        return md.toString();
    }
```

#### 5.2.4 文本切片器 `[P1]`

```java
/**
 * 文本切片服务
 * 使用递归字符分割策略，将长文本切分为适合向量化的段落
 */
@Service
public class TextSplitter {

    @Value("${rag.chunk-size:500}")
    private int chunkSize;       // 切片大小（字符数）

    @Value("${rag.chunk-overlap:50}")
    private int chunkOverlap;    // 重叠大小

    /**
     * 将文本切分为多个片段
     * @param text 原始文本
     * @return 文本片段列表
     */
    public List<String> split(String text) {
        // 1. 按段落初步分割
        List<String> paragraphs = Arrays.asList(text.split("\n\n"));

        // 2. 对于超长段落，递归分割
        List<String> chunks = new ArrayList<>();
        for (String paragraph : paragraphs) {
            if (paragraph.trim().isEmpty()) continue;

            if (paragraph.length() <= chunkSize) {
                chunks.add(paragraph.trim());
            } else {
                // 递归分割长段落
                chunks.addAll(splitLongText(paragraph.trim()));
            }
        }

        // 3. 合并过短的片段
        return mergeShortChunks(chunks);
    }

    /**
     * 递归分割长文本
     */
    private List<String> splitLongText(String text) {
        List<String> result = new ArrayList<>();
        int start = 0;
        while (start < text.length()) {
            int end = Math.min(start + chunkSize, text.length());
            // 尝试在标点/空格处断开
            if (end < text.length()) {
                end = findBreakPoint(text, end);
            }
            result.add(text.substring(start, end).trim());
            start = end - chunkOverlap; // 重叠
            if (start >= text.length()) break;
        }
        return result;
    }

    /**
     * 寻找合适的断点（句号、换行等）
     */
    private int findBreakPoint(String text, int end) {
        int searchStart = Math.max(end - 50, 0);
        String sub = text.substring(searchStart, Math.min(end + 1, text.length()));
        // 优先在句号处断开
        for (char sep : new char[]{'。', '\n', '！', '？', ';', '；', '，', ' '}) {
            int idx = sub.lastIndexOf(sep);
            if (idx >= 0) return searchStart + idx + 1;
        }
        return end;
    }

    /**
     * 合并过短片段到前一个片段
     */
    private List<String> mergeShortChunks(List<String> chunks) {
        List<String> result = new ArrayList<>();
        for (String chunk : chunks) {
            if (!result.isEmpty() && chunk.length() < 100) {
                result.set(result.size() - 1, result.get(result.size() - 1) + "\n" + chunk);
            } else {
                result.add(chunk);
            }
        }
        return result;
    }
}
```

#### 6.2.1 ChatQueryService（RAG 问答核心） `[P1 sync + P2 SSE流式]`

```java
/**
 * 问答查询服务（CQRS 读端）
 * 实现完整的 RAG 检索增强生成流程
 */
@Service
@Slf4j
public class ChatQueryService {

    @Autowired
    private ProviderFactory providerFactory;

    @Autowired
    private HybridRetriever hybridRetriever;       // ★ 混合检索器

    @Autowired
    private PromptTemplate promptTemplate;

    @Autowired
    private ConversationService conversationService;

    @Autowired
    private MessageMapper messageMapper;

    @Autowired
    private ApplicationEventPublisher eventPublisher;

    @Autowired
    private LLMCircuitBreaker circuitBreaker;      // ★ LLM 熔断器

    /**
     * 基于 RAG 的智能问答（流式 SSE）
     *
     * @param query 用户问题
     * @param conversationId 会话ID（null则新建）
     * @param userId 用户ID
     * @param responseEmitter SSE 响应发射器
     */
    public void askStream(String query, Long conversationId, Long userId,
                          SseEmitter responseEmitter) {
        // ===== 1. 会话管理 =====
        if (conversationId == null) {
            conversationId = conversationService.createConversation(userId, query);
        }

        // 保存用户提问
        Message userMsg = saveMessage(conversationId, "user", query, null);

        // ===== 2. 混合检索 =====
        List<RetrievedDocument> retrievedDocs;
        try {
            EmbeddingProvider embedProvider = providerFactory.getEmbeddingProvider();
            float[] queryEmbedding = embedProvider.embed(query);
            // ★ 混合检索：语义 + BM25 → RRF 融合 → Rerank 精排
            retrievedDocs = hybridRetriever.hybridSearch(query, queryEmbedding);
        } catch (Exception e) {
            log.error("文档检索失败", e);
            sendSseEvent(responseEmitter, "error", "知识库检索暂时不可用，请稍后重试");
            responseEmitter.complete();
            return;
        }

        if (retrievedDocs.isEmpty()) {
            sendSseEvent(responseEmitter, "error",
                "知识库中暂无相关信息，请联系管理员上传相关文档");
            responseEmitter.complete();
            return;
        }

        // ===== 3. 构建 Prompt =====
        String contextText = retrievedDocs.stream()
                .map(doc -> "【来源：" + doc.getDocumentTitle() + "】\n" + doc.getContent())
                .collect(Collectors.joining("\n\n---\n\n"));
        String prompt = promptTemplate.build(query, contextText);

        // ===== 4. LLM 熔断器保护 + 流式生成 =====
        List<Message> messages = List.of(
            Message.system("你是一个企业知识库助手，请根据参考资料准确回答用户问题。"),
            Message.user(prompt)
        );

        LLMProvider llmProvider = circuitBreaker.getActiveProvider();
        StringBuilder fullAnswer = new StringBuilder();

        try {
            Flux<String> tokenStream = llmProvider.generateStream(messages);
            tokenStream.subscribe(
                token -> {
                    // ★ 逐 token 通过 SSE 推送到前端
                    fullAnswer.append(token);
                    sendSseEvent(responseEmitter, "token", token);
                },
                error -> {
                    // 流式生成异常
                    log.error("LLM 流式生成失败", error);
                    circuitBreaker.recordFailure();  // 通知熔断器记录失败
                    sendSseEvent(responseEmitter, "error", "AI 回答生成失败");
                    responseEmitter.complete();
                },
                () -> {
                    // 流式生成完成
                    circuitBreaker.recordSuccess();  // 通知熔断器记录成功

                    // 构建来源引用
                    List<SourceVO> sources = retrievedDocs.stream()
                            .map(SourceVO::from)
                            .collect(Collectors.toList());

                    // 保存完整 AI 回答
                    saveMessage(conversationId, "assistant",
                            fullAnswer.toString(), sources);

                    // 发送完成信号（含会话ID和引用来源）
                    Map<String, Object> doneData = new HashMap<>();
                    doneData.put("conversationId", conversationId);
                    doneData.put("sources", sources);
                    sendSseEvent(responseEmitter, "done", doneData);
                    responseEmitter.complete();

                    // 发布统计事件
                    publishStatEvent(userId, conversationId);
                }
            );
        } catch (Exception e) {
            log.error("LLM 调用失败", e);
            sendSseEvent(responseEmitter, "error", "AI 服务暂时不可用，请稍后重试");
            responseEmitter.complete();
        }
    }

    /**
     * 发送 SSE 事件
     */
    private void sendSseEvent(SseEmitter emitter, String eventName, Object data) {
        try {
            emitter.send(SseEmitter.event().name(eventName).data(data));
        } catch (IOException e) {
            log.error("SSE 推送失败", e);
        }
    }

    /**
     * 保存消息到数据库
     */
    private Message saveMessage(Long conversationId, String role,
                                 String content, List<SourceVO> sources) {
        Message msg = new Message();
        msg.setConversationId(conversationId);
        msg.setRole(role);
        msg.setContent(content);
        if (sources != null) {
            msg.setSources(JSON.toJSONString(sources));
        }
        messageMapper.insert(msg);
        // 更新会话消息计数
        conversationService.incrementMessageCount(conversationId);
        return msg;
    }
}
```

#### 6.2.4 OllamaEmbeddingProvider（本地 Embedding 实现） `[P1]`

> **选型说明**（批次 07 · 任务 7.2 回填；替代原 `DeepSeekEmbeddingProvider` 一节）
>
> Embedding 的实际选型是 **本地 Ollama 服务 + `qwen3-embedding:4b`**（2560 维，cosine），
> 这是有意为之的架构决策，而非"未实现"：
>
> | 维度 | 说明 |
> |---|---|
> | 为何不走云端 Embedding API | **DeepSeek 不提供 Embedding API**——原设计基于 OpenAI 兼容接口的 `DeepSeekEmbeddingProvider` 无法实现，该方向已废弃（该方向已从本文档与类映射表中移除） |
> | 数据边界 | 知识库内容（人事/财务文档等）不出本地，避免内容外传给第三方 |
> | 成本与配额 | 向量化调用量按切片计，本地推理无 API 费用与配额限制 |
>
> 配置接线：`application-p1.yml` 的 `embedding.provider: ollama`（Provider 生效开关，被
> `ProviderFactory` 读取）；`application-p2.yml` 的 `ollama.embedding.base-url` /
> `ollama.embedding.model: qwen3-embedding:4b`（模型选型，被本类读取）。
>
> ⚠️ **已知取舍：Embedding 是单点**。LLM 侧有 `deepseek ↔ ollama` 互备与熔断器，
> Embedding 侧只有本地 Ollama 一个来源，服务不可用时向量化链路整体不可用。
> 已确认的处置是 **整批失败 + 失败可见**：批量调用失败时整批 future 以异常完成
> （不再"降级逐条重试"——逐条重试在服务整体不可用时只是把同样的失败调用再做 N 次），
> 连续失败达阈值时输出聚合告警，失败批次整批回退状态并入 DLQ。
> **不引入第二个 Embedding 来源、不引入熔断器**（如后续有高可用需求再另行决策）。

#### 6.2.5 HybridRetriever（混合检索器）★ `[P2]`

```java
/**
 * 混合检索器 —— 语义向量检索 + BM25 关键词检索 + Rerank 重排序
 * 双路召回 → RRF 加权融合 → Rerank 精排 → Top-K 输出
 */
@Component
@Slf4j
public class HybridRetriever {

    @Autowired
    private ChromaRetriever chromaRetriever;    // 语义向量检索

    @Autowired
    private BM25Retriever bm25Retriever;        // 关键词检索

    @Autowired
    private RerankerService rerankerService;    // Rerank 重排序

    @Value("${rag.hybrid.semantic-weight:0.6}")
    private double semanticWeight;

    @Value("${rag.hybrid.keyword-weight:0.4}")
    private double keywordWeight;

    @Value("${rag.retrieval.wide-top-k:20}")
    private int wideTopK;  // 宽召回数量

    @Value("${rag.retrieval.final-top-k:5}")
    private int finalTopK; // 最终返回数量

    /**
     * 混合检索：语义 + 关键词 → 融合 → Rerank → Top-K
     * @param query 用户原始问题
     * @param queryEmbedding 查询向量
     * @return 重排序后的检索结果
     */
    public List<RetrievedDocument> hybridSearch(String query, float[] queryEmbedding) {
        // ===== 1. 双路宽召回 =====
        // 语义检索 Top-K=20
        List<RetrievedDocument> semanticResults =
                chromaRetriever.similaritySearch(queryEmbedding, wideTopK);

        // BM25 关键词检索 Top-K=20
        List<RetrievedDocument> bm25Results =
                bm25Retriever.keywordSearch(query, wideTopK);

        // ===== 2. RRF (Reciprocal Rank Fusion) 加权融合去重 =====
        List<RetrievedDocument> fusedResults = rrfFusion(
                semanticResults, bm25Results, semanticWeight, keywordWeight);

        // ===== 3. Rerank 精排 =====
        List<RetrievedDocument> rerankedResults =
                rerankerService.rerank(query, fusedResults, finalTopK);

        log.info("混合检索完成: 语义={}, BM25={}, 融合后={}, Rerank后={}",
                semanticResults.size(), bm25Results.size(),
                fusedResults.size(), rerankedResults.size());

        return rerankedResults;
    }

    /**
     * RRF 加权融合算法
     * score(doc) = w1 / (k + rank_semantic) + w2 / (k + rank_bm25)
     * 对两路结果按 RRF 分数重新排序，相同内容取最高分
     */
    private List<RetrievedDocument> rrfFusion(
            List<RetrievedDocument> semanticResults,
            List<RetrievedDocument> bm25Results,
            double w1, double w2) {

        final double k = 60.0; // RRF 平滑常数
        Map<String, Double> scoreMap = new HashMap<>();
        Map<String, RetrievedDocument> docMap = new HashMap<>();

        // 语义检索结果计分
        for (int i = 0; i < semanticResults.size(); i++) {
            String key = hashKey(semanticResults.get(i));
            double score = w1 / (k + i + 1);
            scoreMap.merge(key, score, Double::sum);
            docMap.putIfAbsent(key, semanticResults.get(i));
        }

        // BM25 结果计分
        for (int i = 0; i < bm25Results.size(); i++) {
            String key = hashKey(bm25Results.get(i));
            double score = w2 / (k + i + 1);
            scoreMap.merge(key, score, Double::sum);
            docMap.putIfAbsent(key, bm25Results.get(i));
        }

        // 按 RRF 分数降序排列
        return scoreMap.entrySet().stream()
                .sorted(Map.Entry.<String, Double>comparingByValue().reversed())
                .map(e -> docMap.get(e.getKey()))
                .collect(Collectors.toList());
    }

    private String hashKey(RetrievedDocument doc) {
        return String.valueOf(doc.getContent().hashCode());
    }
}
```

#### 6.2.7 LLMCircuitBreaker（LLM 熔断器） `[P2]`

```java
/**
 * LLM 服务熔断器
 * 状态机：CLOSED → OPEN → HALF_OPEN → CLOSED
 *
 * 当 Ollama 连续失败 ≥ 3 次时自动熔断，切换到 DeepSeek API 降级链路
 * 熔断 30 秒后进入半开状态，允许探测请求验证 Ollama 是否恢复
 */
@Component
@Slf4j
public class LLMCircuitBreaker {

    @Autowired
    private ProviderFactory providerFactory;

    /** 熔断状态 */
    private enum State { CLOSED, OPEN, HALF_OPEN }

    /** 当前状态 */
    private volatile State state = State.CLOSED;

    /** 连续失败计数器 */
    private final AtomicInteger failureCount = new AtomicInteger(0);

    /** 熔断开始时间 */
    private volatile long openTimestamp = 0;

    @Value("${circuit-breaker.failure-threshold:3}")
    private int failureThreshold;     // 失败阈值

    @Value("${circuit-breaker.open-duration-ms:30000}")
    private long openDurationMs;      // 熔断时长（毫秒）

    /**
     * 获取当前可用的 LLM Provider
     * 根据熔断状态决定返回 Ollama 还是降级的 DeepSeek
     */
    public LLMProvider getActiveProvider() {
        switch (state) {
            case CLOSED:
                return providerFactory.getLLMProvider(); // 使用配置的默认 Provider

            case OPEN:
                if (System.currentTimeMillis() - openTimestamp > openDurationMs) {
                    // 熔断时间到，进入半开状态
                    state = State.HALF_OPEN;
                    log.info("熔断器: OPEN → HALF_OPEN，尝试探测 Ollama");
                    return providerFactory.getLLMProvider(); // 半开时尝试主 Provider
                }
                // 仍在熔断期，返回降级 Provider
                log.warn("熔断器 OPEN: 使用 DeepSeek 降级链路");
                return providerFactory.getFallbackLLMProvider();

            case HALF_OPEN:
                // 半开状态允许一个探测请求通过
                return providerFactory.getLLMProvider();

            default:
                return providerFactory.getLLMProvider();
        }
    }

    /** 记录调用成功 */
    public void recordSuccess() {
        if (state == State.HALF_OPEN) {
            state = State.CLOSED;
            failureCount.set(0);
            log.info("熔断器: HALF_OPEN → CLOSED，Ollama 已恢复");
        }
        failureCount.set(0); // CLOSED 状态下重置
    }

    /** 记录调用失败 */
    public void recordFailure() {
        int count = failureCount.incrementAndGet();
        if (state == State.CLOSED && count >= failureThreshold) {
            state = State.OPEN;
            openTimestamp = System.currentTimeMillis();
            log.error("熔断器: CLOSED → OPEN，连续失败 {} 次，切换到 DeepSeek 降级", count);
        } else if (state == State.HALF_OPEN) {
            state = State.OPEN;
            openTimestamp = System.currentTimeMillis();
            log.error("熔断器: HALF_OPEN → OPEN，Ollama 探测失败，继续熔断");
        }
    }
}
```

### 7.1 死信队列（DLQ）与指数退避重试 `[P2]`

#### 7.0.1 DeadLetterQueue

```java
/**
 * 死信队列管理器
 * 事件处理失败时写入 dlq_message 表，支持后续重试
 */
@Component
@Slf4j
public class DeadLetterQueue {

    @Autowired
    private DlqMessageMapper dlqMessageMapper;

    /** 最大重试次数 */
    @Value("${dlq.max-retries:4}")
    private int maxRetries;

    /** 指数退避基数（秒） */
    @Value("${dlq.backoff-base:3}")
    private int backoffBase;

    /**
     * 将失败事件写入死信队列
     * @param eventType 事件类型
     * @param documentId 关联文档ID
     * @param payload 事件原始载荷
     * @param error 错误信息
     */
    public void enqueue(String eventType, Long documentId,
                        String payload, String error) {
        DlqMessage msg = new DlqMessage();
        msg.setEventType(eventType);
        msg.setDocumentId(documentId);
        msg.setPayload(payload);
        msg.setErrorMsg(error);
        msg.setRetryCount(0);
        // 首次重试延迟 = backoffBase^1 = 3 秒
        msg.setNextRetryAt(LocalDateTime.now().plusSeconds(backoffBase));
        msg.setStatus("PENDING");
        dlqMessageMapper.insert(msg);
        log.warn("事件进入死信队列: type={}, docId={}, 首次重试延迟={}s",
                eventType, documentId, backoffBase);
    }

    /**
     * 计算指数退避时间
     * retry 0 → 3s, retry 1 → 9s, retry 2 → 27s, retry 3 → 81s
     */
    private long calcBackoffSeconds(int retryCount) {
        return (long) Math.pow(backoffBase, retryCount + 1);
    }

    /**
     * 更新重试状态
     * @param msgId 消息ID
     * @param success 是否成功
     * @param error 失败时的错误信息
     */
    public void updateRetryResult(Long msgId, boolean success, String error) {
        DlqMessage msg = dlqMessageMapper.selectById(msgId);
        if (success) {
            dlqMessageMapper.deleteById(msgId);
            log.info("DLQ 重试成功: msgId={}", msgId);
        } else {
            int newCount = msg.getRetryCount() + 1;
            if (newCount >= maxRetries) {
                dlqMessageMapper.updateStatus(msgId, "DEAD", error);
                log.error("DLQ 重试耗尽: msgId={}, 最终标记为 DEAD", msgId);
                // TODO: 发送告警通知管理员
            } else {
                long nextDelay = calcBackoffSeconds(newCount);
                dlqMessageMapper.updateRetry(msgId, newCount,
                        LocalDateTime.now().plusSeconds(nextDelay), error);
                log.warn("DLQ 重试失败: msgId={}, 第{}次, 下次重试延迟={}s",
                        msgId, newCount, nextDelay);
            }
        }
    }
}
```

#### 7.0.2 DlqRetryScheduler（定时重试调度器）★

> ★ **模块归属变更**：`DlqRetryScheduler` 位于 `agent-qr-web`（而非 `agent-qr-common`），
> 因为重试执行需要注入各业务模块的 Service/Listener（`DocumentParserService`、`ChunkEmbeddingListener`、`DocumentDeleteServiceV2`），
> 而 `agent-qr-common` 不能反向依赖业务模块。`agent-qr-web` 依赖全部模块，是放置跨模块调度逻辑的唯一合理位置。

```java
/**
 * DLQ 重试定时调度器 ★ 位于 agent-qr-web 模块
 *
 * 模块归属说明：
 * - DeadLetterQueue / DlqMessageMapper / DlqMessage → agent-qr-common（纯基础设施）
 * - DlqRetryScheduler → agent-qr-web（跨模块编排，需要注入各业务模块的类）
 * - 各模块也可注册自己的 @Scheduled 重试方法作为补充
 */
@Component
@Slf4j
public class DlqRetryScheduler {

    @Autowired
    private DeadLetterQueue deadLetterQueue;
    @Autowired
    private DlqMessageMapper dlqMessageMapper;

    // ★ 以下依赖来自各业务模块，仅 agent-qr-web 可同时注入
    @Autowired(required = false)
    private DocumentParserService parserService;          // 来自 agent-qr-knowledge
    @Autowired(required = false)
    private ChunkEmbeddingListener chunkEmbeddingListener; // 来自 agent-qr-knowledge
    @Autowired(required = false)
    private DocumentDeleteServiceV2 documentDeleteServiceV2; // ★ 来自 agent-qr-compensation

    /**
     * 每 30 秒扫描一次 DLQ，对到期记录重试
     */
    @Scheduled(fixedDelay = 30000)
    public void retryDeadLetters() {
        List<DlqMessage> pendingMessages =
                dlqMessageMapper.selectPendingRetries(LocalDateTime.now());

        for (DlqMessage msg : pendingMessages) {
            try {
                log.info("DLQ 重试: msgId={}, type={}, retry={}",
                        msg.getId(), msg.getEventType(), msg.getRetryCount());

                // 根据事件类型重新触发处理
                switch (msg.getEventType()) {
                    case "PARSE" -> retryParse(msg);
                    case "CHUNK" -> retryChunk(msg);
                    case "EMBED" -> retryEmbed(msg);
                    case "DELETE" -> retryDelete(msg);  // ★ compensation 模块的物理删除重试
                }

                deadLetterQueue.updateRetryResult(msg.getId(), true, null);
            } catch (Exception e) {
                deadLetterQueue.updateRetryResult(msg.getId(), false, e.getMessage());
            }
        }
    }

    private void retryParse(DlqMessage msg) {
        // 重新发布 DocumentUploadedEvent 触发解析
        DocumentUploadedEvent event = JSON.parseObject(msg.getPayload(), DocumentUploadedEvent.class);
        parserService.parse(event.getFilePath(), event.getFileType());
    }

    private void retryChunk(DlqMessage msg) { /* 类似 retryParse */ }
    private void retryEmbed(DlqMessage msg) { /* 类似 retryParse */ }

    /** ★ DELETE 重试：重新调用 compensation 模块的物理删除 */
    private void retryDelete(DlqMessage msg) {
        List<String> chromaIds = JSON.parseArray(msg.getPayload(), String.class);
        documentDeleteServiceV2.asyncPhysicalDelete(msg.getDocumentId(), chromaIds);
    }
}
```

```java
@Component

            parsedEvent.setContent(content);
            eventPublisher.publishEvent(parsedEvent);

            log.info("文档解析完成: id={}", event.getDocumentId());
        } catch (Exception e) {
            // 4. 解析失败 → 进入死信队列，不直接标记 FAILED
            log.error("文档解析失败: id={}, 进入DLQ", event.getDocumentId(), e);
            documentMapper.updateStatus(event.getDocumentId(), DocumentStatus.FAILED.name());
            documentMapper.updateErrorMsg(event.getDocumentId(), "解析失败: " + e.getMessage());
            // ★ 写入死信队列等待重试
            deadLetterQueue.enqueue("PARSE", event.getDocumentId(),
                    JSON.toJSONString(event), e.getMessage());
        }
    }

    private void updateStatus(Long documentId, DocumentStatus status) {
        documentMapper.updateStatus(documentId, status.name());
    }
}
```

> ★ 本监听器位于 `agent-qr-compensation` 模块（`org.example.agent_qr.compensation.listener`），

```java
/**
 * ★ 文档删除事件监听器 [P2]
 * 位于 agent-qr-compensation 模块，单向依赖 agent-qr-knowledge（访问 Mapper）
 *
 * 设计原则：
 * 1. knowledge 模块只发布 DocumentDeleteRequestedEvent，不注入 compensation 的任何类
 * 2. compensation 模块使用 @TransactionalEventListener(phase = AFTER_COMMIT)
 *    确保在 knowledge 模块的事务提交成功后才执行
 * 3. 异步执行（@Async("deleteExecutor")），不阻塞 Controller 响应
 * 4. 异常进入 DLQ 重试，保证最终一致性
 *
 * 依赖链：compensation → knowledge → common ← compensation（无循环）
 */
@Component
@Slf4j
public class DocumentDeleteListener {

    @Autowired
    private DocumentMapper documentMapper;          // 来自 agent-qr-knowledge
    @Autowired
    private ChunkMapper chunkMapper;                // 来自 agent-qr-knowledge
    @Autowired
    private DocumentDeleteServiceV2 documentDeleteServiceV2;  // 本模块
    @Autowired
    private DeadLetterQueue deadLetterQueue;         // 来自 agent-qr-common

    /**
     * ★ 处理文档删除请求事件
     * @TransactionalEventListener(phase = AFTER_COMMIT) 确保：
     * - knowledge 模块的 DocumentCommandService.requestDeleteDocument() 事务已提交
     * - 文档状态已标记为 DELETING
     * - 此时执行逻辑删除+物理删除是安全的
     *
     * @Async("deleteExecutor") 确保：
     * - 不阻塞 Controller 的 HTTP 响应
     * - 使用独立的删除线程池，与解析/切片/向量化线程池隔离
     */
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    @Async("deleteExecutor")
    public void handleDocumentDeleteRequested(DocumentDeleteRequestedEvent event) {
        log.info("收到文档删除事件: docId={}, chromaIds={}",
            event.getDocumentId(), event.getChromaIds() != null ? event.getChromaIds().size() : 0);

        try {
            // ===== 第 1 步：MySQL 逻辑删除（B+树索引瞬间生效，检索立即过滤） =====
            // 切片逻辑删除
            chunkMapper.softDeleteByDocumentId(event.getDocumentId());
            // 文档主记录逻辑删除
            documentMapper.softDelete(event.getDocumentId());

            log.info("MySQL 逻辑删除完成: docId={}", event.getDocumentId());

            // ===== 第 2 步：ChromaDB 异步物理删除（带重试+DLQ兜底） =====
            if (event.getChromaIds() != null && !event.getChromaIds().isEmpty()) {
                documentDeleteServiceV2.asyncPhysicalDelete(
                    event.getDocumentId(), event.getChromaIds());
            }

        } catch (Exception e) {
            // ===== 异常处理：写入 DLQ 等待重试 =====
            log.error("文档删除监听器执行失败: docId={}, 进入DLQ",
                event.getDocumentId(), e);
            deadLetterQueue.enqueue("DELETE", event.getDocumentId(),
                JSON.toJSONString(event), e.getMessage());
        }
    }
}
```

```java
/**
 * 异步任务线程池配置 [P1 双池 → P2 四池隔离]
 *
 * P2 四池隔离原因：
 * - parseExecutor: PDF/DOCX 解析是 CPU 密集型 + 大内存，独立池防止 OOM 影响其他任务
 * - chunkExecutor: 文本切片是 CPU 密集型，与解析隔离
 * - embedExecutor: 向量化是 IO 密集型（调用外部 API），独立池防止慢 IO 阻塞 CPU 任务
 * - deleteExecutor: ★ 删除是 IO 密集型（ChromaDB API + MySQL），独立池防止慢删除阻塞正常处理
 *   使用 MdcTaskDecorator 确保 TraceId 在线程切换时不丢失
```

```java
/**
 * 数据源连接器策略接口
 * 所有数据源类型（JDBC/REST/S3）统一实现此接口，
```

### 8.7.2 JdbcConnector（JDBC 数据库连接器）

```java
/**
 * JDBC 数据库连接器
 * 支持 MySQL、PostgreSQL、Oracle、SQL Server
 * 增量策略：基于时间戳游标或 Debezium CDC 日志
 */
@Component
@Slf4j
public class JdbcConnector implements DataSourceConnector {

    @Override
    public String getType() { return "JDBC"; }

    @Override
    public ConnectionTestResult testConnection(Map<String, Object> config) {
        String url = (String) config.get("url");
        String username = (String) config.get("username");
        String password = (String) config.get("password");

        try (Connection conn = DriverManager.getConnection(url, username, password)) {
            long start = System.currentTimeMillis();
            DatabaseMetaData meta = conn.getMetaData();
            long latency = System.currentTimeMillis() - start;

            ConnectionTestResult result = new ConnectionTestResult();
            result.setSuccess(true);
            result.setLatencyMs(latency);
            result.setDbProduct(meta.getDatabaseProductName());
            result.setDbVersion(meta.getDatabaseProductVersion());
            return result;
        } catch (SQLException e) {
            ConnectionTestResult result = new ConnectionTestResult();
            result.setSuccess(false);
            result.setErrorMsg(e.getMessage());
            return result;
        }
    }

    @Override
    public SyncResult fullSync(SyncContext context) {
        DataSourceConfig config = context.getConfig();
        List<Map<String, Object>> allRows = new ArrayList<>();

        for (String tableName : config.getTableNames()) {
            String sql = String.format("SELECT * FROM %s", tableName);
            try (Connection conn = getConnection(config);
                 PreparedStatement stmt = conn.prepareStatement(sql);
                 ResultSet rs = stmt.executeQuery()) {

                ResultSetMetaData meta = rs.getMetaData();
                int colCount = meta.getColumnCount();
                while (rs.next()) {
                    Map<String, Object> row = new LinkedHashMap<>();
                    for (int i = 1; i <= colCount; i++) {
                        row.put(meta.getColumnName(i), rs.getObject(i));
                    }
                    allRows.add(row);
                }
            } catch (SQLException e) {
                log.error("全量同步失败: table={}", tableName, e);
                throw new BusinessException("数据库全量同步失败: " + e.getMessage());
            }
        }

        SyncResult result = new SyncResult();
        result.setTotalRows(allRows.size());
        result.setRawData(allRows);
        result.setNextCursor(null); // 全量同步不设游标
        return result;
    }

    @Override
    public SyncResult incrementalSync(SyncContext context, String lastCursor) {
        DataSourceConfig config = context.getConfig();
        String cursorField = config.getCursorField(); // e.g. "update_time"
        List<Map<String, Object>> changedRows = new ArrayList<>();
        String newCursor = lastCursor;

        for (String tableName : config.getTableNames()) {
            String sql = String.format(
                "SELECT * FROM %s WHERE %s > ? ORDER BY %s ASC",
                tableName, cursorField, cursorField);

            try (Connection conn = getConnection(config);
                 PreparedStatement stmt = conn.prepareStatement(sql)) {
                stmt.setString(1, lastCursor);
                try (ResultSet rs = stmt.executeQuery()) {
                    ResultSetMetaData meta = rs.getMetaData();
                    int colCount = meta.getColumnCount();
                    while (rs.next()) {
                        Map<String, Object> row = new LinkedHashMap<>();
                        for (int i = 1; i <= colCount; i++) {
                            row.put(meta.getColumnName(i), rs.getObject(i));
                        }
                        changedRows.add(row);
                        // 更新游标到最后一条记录的 cursor_field 值
                        newCursor = rs.getString(cursorField);
                    }
                }
            } catch (SQLException e) {
                log.error("增量同步失败: table={}", tableName, e);
                throw new BusinessException("数据库增量同步失败: " + e.getMessage());
            }
        }

        SyncResult result = new SyncResult();
        result.setTotalRows(changedRows.size());
        result.setRawData(changedRows);
        result.setNextCursor(newCursor); // 新游标
        return result;
    }
}
```

### 8.7.3 RestApiConnector（REST API 连接器）

```java
/**
 * REST API 数据源连接器
 * 支持分页拉取和 Webhook 推送两种模式
 * 增量策略：基于响应头 X-Next-Cursor 分页 / Webhook 事件回调
 */
@Component
@Slf4j
public class RestApiConnector implements DataSourceConnector {

    @Override
    public String getType() { return "REST"; }

    @Override
    public SyncResult fullSync(SyncContext context) {
        DataSourceConfig config = context.getConfig();
        RestTemplate restTemplate = createRestTemplate(config);
        List<Map<String, Object>> allRecords = new ArrayList<>();

        String nextCursor = null;
        boolean hasMore = true;
        while (hasMore) {
            // 构建请求 URL（带分页参数）
            String url = buildPageUrl(config.getBaseUrl(), nextCursor);
            ResponseEntity<List<Map<String, Object>>> response =
                restTemplate.exchange(url, HttpMethod.GET, null,
                    new ParameterizedTypeReference<>() {});

            List<Map<String, Object>> page = response.getBody();
            if (page != null && !page.isEmpty()) {
                allRecords.addAll(page);
            }

            // 从响应头获取下一页游标
            nextCursor = response.getHeaders().getFirst("X-Next-Cursor");
            hasMore = (nextCursor != null && !nextCursor.isEmpty());
        }

        SyncResult result = new SyncResult();

        result.setRawData(allRecords);

    @Override
    public SyncResult incrementalSync(SyncContext context, String lastCursor) {
        // REST 增量通常通过游标分页实现，逻辑同全量但传入 cursor
        return fullSync(context);
```

### 8.7.4 S3Connector（文件系统连接器）

```java
/**
 * S3 / 文件系统连接器
 * 支持 S3 对象存储、NFS 共享目录、本地目录监听
 * 增量策略：基于文件 lastModified 时间戳过滤
 */
@Component
@Slf4j
public class S3Connector implements DataSourceConnector {

    @Override
    public String getType() { return "S3"; }

    @Override
    public SyncResult fullSync(SyncContext context) {
        DataSourceConfig config = context.getConfig();
        AmazonS3 s3Client = createS3Client(config);

        List<Map<String, Object>> files = new ArrayList<>();
        ListObjectsV2Request request = new ListObjectsV2Request()
                .withBucketName(config.getBucket())
                .withPrefix(config.getPrefix());

        ListObjectsV2Result listResult;
        do {
            listResult = s3Client.listObjectsV2(request);
            for (S3ObjectSummary obj : listResult.getObjectSummaries()) {
                if (isSupportedFormat(obj.getKey())) {
                    Map<String, Object> fileInfo = new HashMap<>();
                    fileInfo.put("key", obj.getKey());
                    fileInfo.put("size", obj.getSize());
                    fileInfo.put("lastModified", obj.getLastModified());
                    fileInfo.put("bucket", config.getBucket());
                    // 下载文件内容
                    S3Object s3Obj = s3Client.getObject(config.getBucket(), obj.getKey());
                    fileInfo.put("content", IOUtils.toString(s3Obj.getObjectContent(), "UTF-8"));
                    files.add(fileInfo);
                }
            }
            request.setContinuationToken(listResult.getNextContinuationToken());
        } while (listResult.isTruncated());

        SyncResult result = new SyncResult();
        result.setTotalRows(files.size());
        result.setRawData(files);
        return result;
    }

    @Override
    public SyncResult incrementalSync(SyncContext context, String lastCursor) {
        // 基于 lastModified > lastCursor 过滤新增/修改文件
        // lastCursor 格式: ISO 8601 时间戳
        DataSourceConfig config = context.getConfig();
        LocalDateTime cursorTime = LocalDateTime.parse(lastCursor);

        // ... 过滤逻辑：只拉取 lastModified > cursorTime 的文件
        // ... 返回新文件和最新文件时间戳作为 newCursor
        return fullSync(context); // 简化示例
    }

    private boolean isSupportedFormat(String key) {
        String lower = key.toLowerCase();
        return lower.endsWith(".pdf") || lower.endsWith(".docx")
            || lower.endsWith(".txt") || lower.endsWith(".md")
            || lower.endsWith(".csv") || lower.endsWith(".json");
    }
}
```

### 8.7.5 SyncScheduler（同步调度器）

```java
/**
 * 数据源同步调度器
 * 根据各数据源配置的 Cron 表达式定时触发同步
 * 同时支持管理员手动触发立即同步
 */
@Component
@Slf4j
public class SyncScheduler {

    @Autowired
    private DataSourceMapper dataSourceMapper;

    @Autowired
    private Map<String, DataSourceConnector> connectorMap; // 自动注入所有 Connector

    @Autowired
    private ApplicationEventPublisher eventPublisher;

    /**
     * 按数据源配置的 Cron 定时触发
     * 使用 Spring @Scheduled + TaskScheduler 动态注册
     */
    public void scheduleSync(Long datasourceId) {
        DataSourceConfig config = dataSourceMapper.selectById(datasourceId);
        if (config == null || !"ACTIVE".equals(config.getStatus())) {
            return;
        }

        DataSourceConnector connector = connectorMap.get(config.getSourceType().toLowerCase());
        if (connector == null) {
            log.error("未找到对应连接器: type={}", config.getSourceType());
            return;
        }

        try {
            // 测试连通性
            connector.testConnection(config.getConnectionConfig());

            // 执行同步（全量或增量）
            SyncResult result;
            if ("FULL".equals(config.getSyncStrategy()) || config.getLastCursor() == null) {
                result = connector.fullSync(buildContext(config));
            } else {
                result = connector.incrementalSync(buildContext(config), config.getLastCursor());
            }

            // 更新数据源状态
            dataSourceMapper.updateSyncResult(datasourceId,
                    result.getNextCursor(), result.getTotalRows(), LocalDateTime.now());

            // ★ 发布数据同步完成事件，触发后续质检+ETL管道
            DataSyncCompletedEvent event = new DataSyncCompletedEvent();
            event.setDatasourceId(datasourceId);
            event.setRawData(result.getRawData());
            event.setSyncBatchId(UUID.randomUUID().toString());
            eventPublisher.publishEvent(event);

            log.info("数据同步完成: source={}, rows={}, batch={}",
                    config.getSourceName(), result.getTotalRows(), event.getSyncBatchId());

        } catch (Exception e) {
            log.error("数据同步失败: source={}", config.getSourceName(), e);
            dataSourceMapper.updateStatus(datasourceId, "ERROR");
        }
    }
}
```

### 8.8.1 DataQualityChecker（质检规则链）

```java
/**
 * 数据质量检查引擎
 * 使用规则链模式，按顺序执行：完整性 → 唯一性 → 格式 → 编码 → 长度
 * 任一维度异常记录到质检报告，合格率<50%自动阻断整批
 */
@Component
@Slf4j
public class DataQualityChecker {

    @Autowired
    private List<QualityRule> rules; // Spring 自动注入所有 QualityRule 实现

    @Value("${dataquality.block-threshold:0.5}")
    private double blockThreshold; // 阻断阈值（合格率），默认 50%

    /**
     * 对同步批次执行全维度质量检查
     * @param batchId 批次号
     * @param rawData 原始数据
     * @return 质检报告
     */
    public QualityReport check(String batchId, List<Map<String, Object>> rawData) {
        QualityReport report = new QualityReport();
        report.setBatchId(batchId);
        report.setTotalCount(rawData.size());

        Set<String> contentHashes = new HashSet<>();
        int totalFailCount = 0;

        // ★ 规则链顺序执行
        for (int i = 0; i < rawData.size(); i++) {
            Map<String, Object> record = rawData.get(i);

            for (QualityRule rule : rules) {
                RuleResult result = rule.evaluate(record);
                if (!result.isPassed()) {
                    report.addFailure(rule.getName(), i, result.getReason());
                    totalFailCount++;
                }
            }

            // 唯一性检查（跨记录）
            String contentHash = hashRecord(record);
            if (!contentHashes.add(contentHash)) {
                report.addFailure("唯一性", i, "内容重复（与已有记录哈希冲突）");
                totalFailCount++;
            }
        }

        int passCount = rawData.size() - (int) report.getFailures().stream()
                .map(QualityFailure::getRecordIndex).distinct().count();
        report.setPassCount(passCount);
        report.setFailCount(rawData.size() - passCount);
        report.setPassRate((double) passCount / rawData.size());

        // ★ 合格率低于阈值 → 阻断
        report.setBlocked(report.getPassRate() < blockThreshold);

        log.info("质检完成: batch={}, total={}, pass={}, fail={}, rate={:.2f}, blocked={}",
                batchId, rawData.size(), passCount,
                rawData.size() - passCount, report.getPassRate(), report.isBlocked());

        return report;
    }

    private String hashRecord(Map<String, Object> record) {
        String content = record.values().stream()
                .map(v -> v != null ? v.toString() : "").collect(Collectors.joining("|"));
        return DigestUtils.md5Hex(content); // MD5 仅用于哈希计算，非密码场景
    }
}
```

### 8.8.2 质检规则实现示例

```java
/** 质检规则接口 */
public interface QualityRule {
    String getName();
    RuleResult evaluate(Map<String, Object> record);
}

/** 完整性检查：必填字段非空 */
@Component
public class CompletenessRule implements QualityRule {
    @Override public String getName() { return "完整性"; }

    @Override
    public RuleResult evaluate(Map<String, Object> record) {
        // 检查 title/content 等关键字段是否为空
        Object content = record.getOrDefault("content", record.getOrDefault("text", null));
        if (content == null || content.toString().trim().isEmpty()) {
            return RuleResult.fail("内容字段为空，无法生成有效知识片段");
        }
        return RuleResult.pass();
    }
}

/** 编码检查：自动检测并标记非 UTF-8 */
@Component
public class EncodingRule implements QualityRule {
    @Override public String getName() { return "编码"; }

    @Override
    public RuleResult evaluate(Map<String, Object> record) {
        for (Map.Entry<String, Object> entry : record.entrySet()) {
            if (entry.getValue() instanceof String text) {
                Charset detected = CharsetDetector.detect(text);
                if (detected != StandardCharsets.UTF_8) {
                    return RuleResult.fail(
                        String.format("字段 '%s' 编码为 %s，需转UTF-8",
                            entry.getKey(), detected.displayName()));
                }
            }
        }
        return RuleResult.pass();
    }
}
```

### 8.8.3 DataQualityService（质检报告服务）

> ★ **方案 B 回填（批次 10 · 任务 10.4.1，问题 26）**：失败明细采用
> **`quality_report.failures` JSON 列**持久化，由 MyBatis-Plus `JacksonTypeHandler`
> 自动序列化/反序列化——**不建 `quality_failure` 表、不存在 `QualityFailureMapper`**。
> 本节及 §8.8.5 / §8.8.6 / §8.8.7 / §12.0 / §12.5 均已按此方案回填。
> 选择 JSON 列而非独立失败明细表的原因：明细始终随报告整体读写（无按明细独立查询的场景），
> 一张表 + 一次 insert 即可满足 drill-down 需求，省去逐条落库与关联查询。

```java
/**
 * 数据质量报告服务。
 * <p>
 * 封装质检引擎调用、报告持久化和分页查询，
 * 在数据源同步完成后由 DataSourceService 调用。
 * </p>
 * <p>
 * 方案 B：failures 明细以 JSON 列存储在 quality_report 表中，
 * 由 MyBatis-Plus JacksonTypeHandler 自动序列化/反序列化，无需额外 Mapper。
 * </p>
 */
@Service
@Slf4j
@RequiredArgsConstructor
public class DataQualityService {

    private final DataQualityChecker checker;
    private final QualityReportMapper reportMapper;
    private final ApplicationEventPublisher eventPublisher;

    /**
     * 对同步批次执行质量检查并持久化报告。
     *
     * @param batchId 同步批次 ID
     * @param rawData 原始数据
     * @return 持久化后的质量报告
     */
    @Transactional
    public QualityReport executeAndSave(String batchId, List<Map<String, Object>> rawData) {
        // 1. 执行规则链检查
        QualityReport report = checker.check(batchId, rawData);

        // 2. 持久化报告（failures 由 JacksonTypeHandler 自动转为 JSON 列）
        reportMapper.insert(report);

        // 3. 发布质检通过事件 → 触发 ETL 管道
        if (!report.isBlocked()) {
            eventPublisher.publishEvent(new DataQualityPassedEvent(
                    batchId, report.getPassCount(), report.getTotal()));
            log.info("质检通过事件已发布: batchId={}, passRate={}", batchId, report.getRate());
        } else {
            log.warn("质检被阻断: batchId={}, passRate={}", batchId, report.getRate());
        }

        return report;
    }

    /**
     * 分页查询质检报告列表，支持按阻断状态筛选。
     *
     * @param page    页码（从 1 开始）
     * @param size    每页条数
     * @param blocked 阻断状态筛选（可选，null 表示不筛选）
     * @return 分页结果
     */
    public Map<String, Object> listReports(int page, int size, Boolean blocked) {
        IPage<QualityReport> ipage = new Page<>(page, size);
        LambdaQueryWrapper<QualityReport> wrapper = new LambdaQueryWrapper<>();
        if (blocked != null) {
            wrapper.eq(QualityReport::isBlocked, blocked);
        }
        wrapper.orderByDesc(QualityReport::getCreateTime);
        IPage<QualityReport> result = reportMapper.selectPage(ipage, wrapper);

        Map<String, Object> pageResult = new HashMap<>();
        pageResult.put("total", result.getTotal());
        pageResult.put("page", page);
        pageResult.put("size", size);
        pageResult.put("records", result.getRecords());
        return pageResult;
    }

    /**
     * 根据批次 ID 查询质检报告详情（含失败明细）。
     *
     * @param batchId 同步批次 ID
     * @return 质检报告（failures 已由 JacksonTypeHandler 自动反序列化）
     */
    public QualityReport getReportByBatchId(String batchId) {
        QualityReport report = reportMapper.selectByBatchId(batchId);
        if (report == null) {
            throw new BusinessException("质检报告不存在: batchId=" + batchId);
        }
        // 失败明细随报告同列存储，无需二次查询
        return report;
    }
}
```

### 8.9.1 DataNormalizer（数据标准化引擎）

```java
/**
 * 数据标准化引擎
 * 将多源异构数据统一为 Canonical 格式
 * 管道：分类 → 字段映射 → 字典翻译 → 格式统一 → 结构化转换 → Canonical 输出
 */
@Component
@Slf4j
public class DataNormalizer {

    @Autowired
    private FieldMappingEngine fieldMappingEngine;

    @Autowired
    private StructuredDataConverter structuredConverter;

    /**
     * 对质检合格的原始数据进行标准化
     * @param rawData 质检合格的原始数据
     * @param config 数据源配置（含字段映射、字典等）
     * @return Canonical 标准记录列表
     */
    public List<CanonicalRecord> normalize(List<Map<String, Object>> rawData,
                                            DataSourceConfig config) {
        List<CanonicalRecord> records = new ArrayList<>();

        for (Map<String, Object> raw : rawData) {
            // 1. 数据分类
            DataType dataType = classify(raw, config);

            // 2. 字段映射 + 字典翻译 + 格式统一
            Map<String, Object> mapped = fieldMappingEngine.apply(raw, config);

            // 3. 转换为 Canonical 格式
            CanonicalRecord record = new CanonicalRecord();
            record.setSourceSystem(config.getSourceName());
            record.setDomain(config.getDomain());
            record.setDataType(dataType);
            record.setMetadata(buildMetadata(mapped, config));

            // 4. 根据数据类型生成 canonical_text
            switch (dataType) {
                case STRUCTURED -> // ★ 结构化 → 自然语言段落
                    record.setCanonicalText(structuredConverter.convert(mapped, config));
                case SEMI_STRUCTURED -> // 半结构化 → 提取关键字段 + 原文
                    record.setCanonicalText(extractSemiStructured(mapped));
                case UNSTRUCTURED -> // 非结构化 → 直接透传原始文本
                    record.setCanonicalText((String) mapped.getOrDefault("content", ""));
            }

            records.add(record);
        }
        return records;
    }

    /** 自动分类：检查数据特征判断类型 */
    private DataType classify(Map<String, Object> record, DataSourceConfig config) {
        if ("JDBC".equals(config.getSourceType())) return DataType.STRUCTURED;
        if (record.containsKey("_file_type")) return DataType.UNSTRUCTURED;
        if (record.containsKey("_json_path") || record.containsKey("_xml_path"))
            return DataType.SEMI_STRUCTURED;
        return DataType.UNSTRUCTURED;
    }
}
```

### 8.9.2 StructuredDataConverter（结构化→自然语言转换）

```java
/**
 * 结构化数据 → 自然语言文本转换器
 * 核心功能：将数据库表行/CSV行转为语义完整的自然语言描述段落
 *
 * 输入：{emp_name:"张三", dept_code:"D01", salary:15000, hire_date:"2024-01-15"}
 * 输出："员工张三，所属部门为研发部，月薪15000元，入职日期为2024年1月15日。"
 */
@Component
public class StructuredDataConverter {

    /**
     * 将结构化行记录转为自然语言段落
     * @param mappedRecord 字段映射后的记录（key=canonical_field）
     * @param config 数据源配置（含字段模板和字典）
     * @return 自然语言描述
     */
    public String convert(Map<String, Object> mappedRecord, DataSourceConfig config) {
        StringBuilder sb = new StringBuilder();
        sb.append("【").append(config.getSourceName()).append("】");

        // 添加表/实体注释作为段落标题
        if (mappedRecord.containsKey("_table_comment")) {
            sb.append(" - ").append(mappedRecord.get("_table_comment"));
        }
        sb.append("\n");

        // 按优先级排序字段
        List<FieldMapping> sortedFields = config.getFieldMappings().stream()
                .filter(f -> "ACTIVE".equals(f.getStatus()))
                .sorted(Comparator.comparingInt(FieldMapping::getPriority))
                .collect(Collectors.toList());

        for (FieldMapping field : sortedFields) {
            Object rawValue = mappedRecord.get(field.getCanonicalField());
            if (rawValue == null) continue;

            // 应用字典翻译
            String displayValue = applyDictionary(rawValue.toString(), field.getDictMapping());

            // 应用格式转换（日期、数字等）
            displayValue = applyFormat(displayValue, field);

            // 使用自然语言模板生成文本
            // 模板示例："{字段中文名}为{值}{单位}"
            String template = field.getTemplate() != null
                    ? field.getTemplate()
                    : field.getDisplayName() + "为{值}";

            String text = template.replace("{字段中文名}", field.getDisplayName())
                                  .replace("{值}", displayValue)
                                  .replace("{单位}", field.getUnit() != null ? field.getUnit() : "");
            sb.append(text).append("，");
        }

        sb.append("\n");
        return sb.toString();
    }

    /**
     * 应用字典翻译
     * 将源系统的编码值翻译为可读的自然语言
     * 示例："D01" → "研发部", "M" → "男"
     */
    private String applyDictionary(String value, Map<String, String> dictMapping) {
        if (dictMapping == null || dictMapping.isEmpty()) return value;
        return dictMapping.getOrDefault(value, value);
    }

    /**
     * 应用格式转换
     * 日期: 2024-01-15 → 2024年1月15日
     * 金额: 15000.00 → 15,000
     */
    private String applyFormat(String value, FieldMapping field) {
        if (field.getTransformRule() == null) return value;

        return switch (field.getTransformRule()) {
            case "DATE_TO_CHINESE" -> convertDateToChinese(value);
            case "MONEY_FORMAT" -> String.format("%,.0f", Double.parseDouble(value));
            case "PERCENTAGE" -> String.format("%.1f%%", Double.parseDouble(value) * 100);
            default -> value;
        };
    }
}
```

### 8.10.2 DomainRouter（业务域路由器）

```java
/**
 * 业务域路由器 —— RAG 检索时的域裁剪
 *
 * 用户提问 → NLP 提取关键实体 → 匹配知识目录 → 筛选检索域 → 精准检索
 * 将全库盲搜变为域内精准搜索，大幅提升检索精度和速度
 */
@Component
@Slf4j
public class DomainRouter {

    @Autowired
    private KnowledgeCatalogService catalogService;

    /**
     * 根据用户问题路由到相关业务域
     * @param query 用户原始问题
     * @return 匹配的业务域列表 + 权重（用于检索过滤和加权）
     */
    public DomainRoutingResult route(String query) {
        CatalogTree catalog = catalogService.getCatalogTree();

        // 1. NLP 实体词提取（可集成 IK Analyzer 或 jieba 分词）
        List<String> keywords = extractKeywords(query);

        // 2. 匹配目录中的域和数据实体
        Map<String, Double> domainScores = new HashMap<>();
        List<String> matchedEntities = new ArrayList<>();

        for (DomainNode domain : catalog.getDomains()) {
            double score = 0.0;

            // 域名匹配
            if (containsAny(query, domain.getDomainName())) {
                score += 0.5;
            }

            // 数据源名匹配
            for (SourceNode source : domain.getSources()) {
                if (containsAny(query, source.getSourceName())) {
                    score += 0.3;
                }
                // 实体名匹配
                for (EntityNode entity : source.getEntities()) {
                    if (containsAny(query, entity.getEntityName())) {
                        score += 0.4;
                        matchedEntities.add(entity.getEntityName());
                    }
                }
            }

            if (score > 0) {
                domainScores.put(domain.getDomainName(), score);
            }
        }

        // 3. 返回路由结果（用于检索时的 metadata 过滤）
        DomainRoutingResult result = new DomainRoutingResult();
        result.setMatchedDomains(domainScores);
        result.setMatchedEntities(matchedEntities);

        // 若未匹配到任何域，回退到全库检索
        result.setFallbackToGlobal(domainScores.isEmpty());

        log.info("检索路由: query='{}', matchedDomains={}, entities={}, fallback={}",
                query, domainScores.keySet(), matchedEntities, result.isFallbackToGlobal());

        return result;
    }

    /**
     * 构建 ChromaDB 检索的 metadata 过滤条件
     * 将路由结果转换为向量数据库的过滤表达式
     */
    public Map<String, String> buildRetrievalFilter(DomainRoutingResult routing) {
        if (routing.isFallbackToGlobal()) {
            return Collections.emptyMap(); // 全库检索，不过滤
        }

        // 只检索匹配域的数据
        Map<String, String> filter = new HashMap<>();
        filter.put("domain", String.join(",", routing.getMatchedDomains().keySet()));
        return filter;
    }
}
```

```java
/**
 * MySQL 前置结构化过滤服务
 * 将 LLM 提取的过滤条件转为 MySQL B+树查询，产出 chunk_id 候选集
 * ChromaDB 仅在候选集（≤ 500 条）内做语义检索，延迟从 3-5s 降至 50-100ms
 */
@Service
@Slf4j
public class StructuredFilterService {

    @Autowired
    private ChunkStructuredMapper structuredMapper;

    /**
     * 根据结构化条件在 MySQL 中过滤出候选 chunk_id 集合
     * @param domain 业务域
     * @param conditions LLM 提取的过滤条件列表
     * @return chunk_id 候选集（上限 500 条）
     */
    public List<Long> filterChunkIds(String domain, List<FilterCondition> conditions) {
        if (conditions == null || conditions.isEmpty()) {
            return Collections.emptyList();
        }

        List<Set<Long>> idSets = new ArrayList<>();
        for (FilterCondition cond : conditions) {
            Set<Long> ids = switch (cond.getFieldType()) {
                case NUMBER -> structuredMapper.selectChunkIdsByNumberRange(
                    domain, cond.getFieldName(),
                    cond.getNumericMin(), cond.getNumericMax());
                case DATE -> structuredMapper.selectChunkIdsByDateRange(
                    domain, cond.getFieldName(),
                    cond.getDateMin(), cond.getDateMax());
                case ENUM, STRING -> structuredMapper.selectChunkIdsByStringValue(
                    domain, cond.getFieldName(), cond.getStringValue());
                default -> Set.of();
            };
            if (!ids.isEmpty()) {
                idSets.add(ids);
            }
        }

        // ★ 多条件交集（AND 语义）
        if (idSets.isEmpty()) return Collections.emptyList();
        Set<Long> result = new HashSet<>(idSets.get(0));
        for (int i = 1; i < idSets.size(); i++) {
            result.retainAll(idSets.get(i));
        }

        // ★ 截断到 500 条，防止候选集过大
        return result.stream().limit(500).collect(Collectors.toList());
    }
}
```

### 8.14.1 BatchEmbeddingService

```java
/**
 * 批量向量化聚合服务
 * BlockingQueue 攒批 + 多消费者并发
 * 50 万切片从 27 小时（逐条调用）→ 16 分钟（批量+并发，100倍提升）
 */
@Component
@Slf4j
public class BatchEmbeddingService {

    @Autowired private ProviderFactory providerFactory;

    /** ★ 攒批队列 */
    private final BlockingQueue<ChunkEmbedTask> batchQueue =
        new LinkedBlockingQueue<>(2000);

    @Value("${embedding.batch.size:32}")
    private int batchSize;

    @Value("${embedding.batch.timeout-ms:100}")
    private int batchTimeoutMs;

    @PostConstruct
    public void startConsumers() {
        int consumers = Runtime.getRuntime().availableProcessors();
        for (int i = 0; i < consumers; i++) {
            new Thread(this::consumeBatch, "embed-batch-" + i).start();
        }
        log.info("批量向量化消费者启动: {} 个线程, batchSize={}", consumers, batchSize);
    }

    /** 提交单个切片到攒批队列 */
    public CompletableFuture<float[]> submit(Chunk chunk) {
        CompletableFuture<float[]> future = new CompletableFuture<>();
        batchQueue.offer(new ChunkEmbedTask(chunk, future));
        return future;
    }

    /** 消费者循环：攒批 → 批量 API → 分发结果 */
    private void consumeBatch() {
        List<ChunkEmbedTask> batch = new ArrayList<>(batchSize);
        long deadline = System.currentTimeMillis() + batchTimeoutMs;

        while (true) {
            try {
                long remaining = deadline - System.currentTimeMillis();
                // ★ 条件触发：攒满 OR 超时
                if (remaining <= 0 || batch.size() >= batchSize) {
                    if (!batch.isEmpty()) {
                        executeBatch(batch);
                        batch.clear();
                        deadline = System.currentTimeMillis() + batchTimeoutMs;
                    }
                }
                ChunkEmbedTask task = batchQueue.poll(
                    Math.max(remaining, 1), TimeUnit.MILLISECONDS);
                if (task != null) batch.add(task);
            } catch (InterruptedException e) { break; }
        }
    }

    /** ★ 一次 API 调用处理一批；★ 失败语义 = 整批失败（批次 07 · 任务 7.2.5） */
    private void executeBatch(List<ChunkEmbedTask> batch) {
        List<String> texts = batch.stream()
            .map(t -> t.chunk.getContent()).toList();
        try {
            List<float[]> embeddings = providerFactory.getEmbeddingProvider()
                .embedBatch(texts);
            if (embeddings.size() != batch.size()) {
                // 安全阀：按索引配对，数量不符必须整批失败（真批量端点的部分失败/截断）
                throw new IllegalStateException("批量向量化返回数量不匹配");
            }
            for (int i = 0; i < batch.size(); i++) {
                batch.get(i).future.complete(embeddings.get(i));
            }
            log.debug("批量向量化: {}条完成", batch.size());
        } catch (Exception e) {
            // ★ 整批失败（原为"降级为逐条重试"）：不再重复调用同样会失败的 embed()
            //    连续失败达阈值 → 聚合告警（失败可见）；整批入一次 DLQ
            for (ChunkEmbedTask task : batch) {
                task.future.completeExceptionally(e);
            }
        }
    }

    private record ChunkEmbedTask(Chunk chunk, CompletableFuture<float[]> future) {}
}
```

### 8.15.6 DomainRouter v2 — Embedding 语义路由 `[P3]`

```java
@Component
public class DomainRouterV2 {
    @Autowired private EmbeddingProvider embeddingProvider;
    private final Map<String, float[]> domainEmbeddings = new ConcurrentHashMap<>();

    /** ★ 用域描述文本预计算 Embedding（启动时执行一次） */
    @PostConstruct
    public void init() {
        Map.of(
            "HR", "人力资源管理、员工信息、薪资福利、绩效考核、招聘培训、组织架构、考勤制度",
            "FINANCE", "财务管理、会计核算、预算控制、报销审批、税务申报、审计合规",
            "RD", "研发管理、产品设计、技术规范、代码标准、测试用例、项目迭代管理",
            "SALES", "销售管理、客户关系、合同管理、报价体系、市场分析、渠道管理"
        ).forEach((domain, desc) -> domainEmbeddings.put(domain, embeddingProvider.embed(desc)));
    }

    /** ★ query 向量与各域向量做余弦相似度匹配 */
    public DomainRoutingResult route(String query) {
        float[] queryEmb = embeddingProvider.embed(query);
        Map<String, Double> scores = new TreeMap<>();
        domainEmbeddings.forEach((domain, emb) -> {
            double sim = cosineSimilarity(queryEmb, emb);
            if (sim > 0.3) scores.put(domain, sim);
        });
        if (scores.isEmpty()) return DomainRoutingResult.fallback();
        return DomainRoutingResult.routed(scores.entrySet().stream()
            .sorted(Map.Entry.<String, Double>comparingByValue().reversed())
            .limit(2).collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue)));
    }
}
```

> **⚠️ 可达性说明（批次 10 · 任务 10.5.6 / R27，2026-10-07 补充）**
>
> 语义/关键词路由的启用方式由 `agent-qr.routing.mode`（`keyword` | `semantic` | `auto`）控制，
> 该键由 `ChatQueryService` 以 `@Value` 真实读取（有启动日志、有单测）。
> **但经 HTTP 入口（`/api/chat/**`）进入的请求恒按"请求指定的域"检索，模式分支不可达**：
> `ChatController.requireDomain()` 强制 `domain` 非空（批次 03 的越权防护决策），
> 而 `ChatQueryService.resolveRouting()` 在 `domain` 非空时直接锁定该域并返回，
> 不会进入模式 switch。
>
> 该开关定位为**内部调用 / 预留能力**：`domain == null` 的内部调用（当前仓库内无 HTTP 调用方）
> 以及将来若开放"自动路由"入口时的免改码切换。
> ❌ **不得**为让它生效而放宽 `domain` 强制——那会重开"不传域即全局检索"的越权绕过路径。
>
> 同节参数 `agent-qr.routing.similarity-threshold` / `agent-qr.routing.top-k` 确有读取点
> （`DomainRouterV2` 的路由打分），非死配置。

### 10.1 依赖设计分析：循环依赖解耦方案 ★

#### 问题描述

若按直觉设计，`agent-qr-knowledge` 和 `agent-qr-compensation` 之间会形成 Maven 循环依赖：

```
┌──────────────────────────────────────────────────────────────────┐
│  ★ 错误设计（循环依赖）                                           │
│                                                                   │
│  knowledge ──需要调用──→ compensation (DocumentDeleteServiceV2)    │
│  compensation ──需要调用──→ knowledge (ChunkMapper/DocumentMapper) │
│                                                                   │
│  形成循环：knowledge → compensation → knowledge                    │
│  Maven 编译失败！                                                  │
└──────────────────────────────────────────────────────────────────┘
```

#### 解耦方案：事件驱动架构

```
┌──────────────────────────────────────────────────────────────────┐
│  ★ 正确设计（事件驱动解耦）                                        │
│                                                                   │
│  ┌──────────────┐    发布 DocumentDeleteRequestedEvent    ┌──────────────────┐  │
│  │  knowledge   │────────────────────────────────────────→│  compensation    │  │
│  │              │    (事件定义在 agent-qr-common)           │                  │  │
│  │  Controller  │                                         │  DeleteListener  │  │
│  │  .requestDel │  ← 不注入 compensation 的任何类          │  .handleDelete   │  │
│  │  eteDocument │                                         │  Requested()     │  │
│  │  ()          │                                         │                  │  │
│  │       │      │                                         │        │         │  │
│  │       │      │                                         │        ▼         │  │
│  │       ▼      │                                         │  MySQL 逻辑删除   │  │
│  │  发布事件     │                                         │  +               │  │
│  │  立即返回     │                                         │  ChromaDB 物理删 │  │
│  └──────────────┘                                         └────────┬─────────┘  │
│       │                                                            │             │
│       │                      依赖关系                               │             │
│       │           compensation ──单向依赖──→ knowledge              │             │
│       │           (访问 ChunkMapper, DocumentMapper)               │             │
│       │                                                            │             │
│       └──────────→ 都依赖 common（DocumentDeleteRequestedEvent） ←──┘             │
│                                                                   │
│  依赖链：compensation → knowledge → common ← compensation          │
│  通过 common 事件类解耦 —— 无循环依赖！                             │
└──────────────────────────────────────────────────────────────────┘
```

#### 关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | `DocumentDeleteRequestedEvent` 定义在 `agent-qr-common` | 双方都依赖 common，不产生直接依赖 |
| 2 | knowledge 只发布事件，不注入 compensation 类 | `DocumentCommandService.requestDeleteDocument()` 仅调用 `eventPublisher.publishEvent()` |
| 3 | compensation 使用 `@TransactionalEventListener(phase = AFTER_COMMIT)` | 确保 knowledge 事务提交后才执行，保证数据一致性 |
| 4 | compensation 使用 `@Async("deleteExecutor")` | 异步执行，不阻塞 Controller HTTP 响应 |
| 5 | 异常进入 DLQ | 逻辑删除/物理删除失败时写入死信队列，由 `DlqRetryScheduler` 重试 |
| 6 | `OrphanVectorScanner` 作为最终兜底 | 每 30 分钟扫描 ChromaDB 孤儿向量，处理 DLQ 耗尽后的残留数据 |

#### 整体一致性保证链

```
用户删除请求
    │
    ▼
KnowledgeController.delete(id)
    │
    ▼
DocumentCommandService.requestDeleteDocument(id)     ← knowledge 模块
    │ 1. 标记 DELETING
    │ 2. 收集 chromaIds
    │ 3. publishEvent(DocumentDeleteRequestedEvent)
    │ 4. return 200（立即响应）
    ▼
DocumentDeleteListener.handleDocumentDeleteRequested() ← compensation 模块
    │ @TransactionalEventListener(phase = AFTER_COMMIT)
    │ @Async("deleteExecutor")
    │
    ├─→ MySQL 逻辑删除（chunkMapper.softDeleteByDocumentId + documentMapper.softDelete）
    │   ★ 检索立即过滤：SELECT ... WHERE deleted = 0
    │
    └─→ ChromaDB 物理删除（DocumentDeleteServiceV2.asyncPhysicalDelete）
        │ 成功 → deleteTaskMapper.updateStatus(DONE)
        │ 失败 → 重试 3 次 → deadLetterQueue.enqueue("DELETE", ...)
        │
        └─→ DlqRetryScheduler 定时重试（指数退避：3s→9s→27s→81s）
            │ 成功 → 删除 DLQ 记录
            │ 4 次全失败 → 标记 DEAD + 告警
            │
            └─→ OrphanVectorScanner 最终兜底（每 30 分钟扫描清理）
```

### 10.2 OrphanVectorScanner（孤儿向量扫描清理） `[P2]`

> 详细设计同 [§8.5.1](#851-orphanvectorscanner孤儿向量扫描清理)（原 §8.5 内容已迁移至此处）
>
> `OrphanVectorScanner` 依赖 `ChunkMapper` 和 `DocumentMapper`（来自 `agent-qr-knowledge`），
> 这是 compensation → knowledge 单向依赖的合理体现。

> **⚠️ 批次 07 · 任务 7.0.11 更正（实测）**：下文示例里的 `chromaVectorStore.getAllDocumentIds()`
> **不存在**，且照此实现的核对会静默跑空。实测（ChromaDB 1.0.0）得到的真实约束有三条：
>
> 1. **向量的 id 是 UUID**，切片 id 存在元数据的 **`chunk_id`** 键里——"向量 id ↔ chunk.id"**不能直接比对**，
>    必须走元数据（`SELECT string_value FROM embedding_metadata WHERE key = 'chunk_id'`）；
> 2. ChromaDB v2 的 **`/get` 只接受 collection ID**（传名称报
>    `Collection ID is not a valid UUIDv4`），必须先按名称解析出 ID；
> 3. `/get` 支持 `limit` / `offset` 分页与 `where: {"chunk_id": {"$in": [...]}}` 元数据过滤。
>
> 已落地的公共能力在 `agent-qr-rag` 的 `ChromaRetriever`（**批次 08 的孤儿扫描请直接复用**）：
>
> | 方法 | 用途 |
> |---|---|
> | `enumerateVectors(limit, offset)` | 分页枚举向量记录（id + chunk_id/document_id/datasource_id/title） |
> | `enumerateAllVectors()` | 全量枚举（内部自动分页） |
> | `findVectorIdsByChunkIds(Collection<Long>)` | chunkId → 向量 UUID 反查（幂等写"先删后写"的前置查询） |
> | `vectorIdFor(Long chunkId)` | 由 chunkId 确定性派生向量 UUID（重跑得到同一 id） |

```java
/**
 * 孤儿向量扫描器
 * 定时扫描 ChromaDB 中存在但 MySQL 中已逻辑删除/物理删除的切片向量，自动清理
 * 作为最终一致性兜底机制，保证 MySQL 与 ChromaDB 间的最终一致性
 */
@Component
@Slf4j
public class OrphanVectorScanner {

    @Autowired
    private ChunkMapper chunkMapper;           // 来自 agent-qr-knowledge
    @Autowired
    private ChromaVectorStore chromaVectorStore;
    @Autowired
    private DocumentMapper documentMapper;      // 来自 agent-qr-knowledge

    /**
     * 每 30 分钟执行一次孤儿向量扫描
     */
    @Scheduled(fixedDelay = 1800000)
    public void scanAndCleanOrphanVectors() {
        log.info("开始扫描孤儿向量...");

        // 1. 获取 ChromaDB 中所有向量的 document_id 元数据
        List<String> chromaDocIds = chromaVectorStore.getAllDocumentIds();

        // 2. 在 MySQL 中查询哪些文档已不存在或已逻辑删除
        List<String> orphanDocIds = chromaDocIds.stream()
                .filter(docId -> {
                    try {
                        Long id = Long.parseLong(docId);
                        Document doc = documentMapper.selectById(id);
                        // 文档不存在 或 已逻辑删除 → 孤儿向量
                        return doc == null || doc.getDeleted() == 1;
                    } catch (NumberFormatException e) {
                        return true; // 异常数据也清理
                    }
                })
                .collect(Collectors.toList());

        // 3. 批量删除孤儿向量
        if (!orphanDocIds.isEmpty()) {
            for (String docId : orphanDocIds) {
                chromaVectorStore.deleteByMetadata("document_id", docId);
            }
            log.warn("清理孤儿向量完成: 共清理 {} 个文档的向量数据", orphanDocIds.size());
        } else {
            log.info("未发现孤儿向量");
        }
    }
}
```

### 10.4 DocumentDeleteServiceV2（物理删除服务） `[P2]`

> 完整类设计见 [§8.12 文档删除一致性设计 v2](#812-文档删除一致性设计-v2修正方案二-p2)
>
> 核心要点：
> - 只负责 ChromaDB 物理删除（MySQL 逻辑删除由 `DocumentDeleteListener` 完成）
> - 创建 `DeleteTask` 记录追踪删除状态
> - 失败时写入 DLQ（指数退避重试：3s→9s→27s→81s，最多 4 次）
> - `OrphanVectorScanner` 作为最终兜底清理

**方法签名更新**：

```java
@Service
@Slf4j
public class DocumentDeleteServiceV2 {

    @Autowired private ChromaVectorStore chromaVectorStore;
    @Autowired private DeleteTaskMapper deleteTaskMapper;
    @Autowired private DeadLetterQueue deadLetterQueue;

    /**
     * ★ 异步物理删除 ChromaDB 向量（由 DocumentDeleteListener 调用）
     * MySQL 逻辑删除已在 Listener 中完成，此处只负责 ChromaDB 物理删除
     *
     * @param documentId 文档ID
     * @param chromaIds ChromaDB 向量ID列表
     */
    @Async("deleteExecutor")
    public void asyncPhysicalDelete(Long documentId, List<String> chromaIds) {
        // 1. 创建 DeleteTask 记录
        DeleteTask task = new DeleteTask();
        task.setDocumentId(documentId);
        task.setChromaIds(JSON.toJSONString(chromaIds));
        task.setStatus("PENDING");
        deleteTaskMapper.insert(task);

        // 2. 调用 ChromaDB DELETE API 物理删除
        try {
            chromaVectorStore.deleteByIds(chromaIds);
            deleteTaskMapper.updateStatus(task.getId(), "DONE");
            log.info("ChromaDB 物理删除成功: docId={}, count={}", documentId, chromaIds.size());
        } catch (Exception e) {
            log.error("ChromaDB 物理删除失败: taskId={}, docId={}", task.getId(), documentId, e);
            deleteTaskMapper.incrementRetryCount(task.getId());
            deleteTaskMapper.updateStatus(task.getId(), "FAILED");
            // ★ 进入 DLQ 重试（指数退避）
            deadLetterQueue.enqueue("DELETE", documentId,
                JSON.toJSONString(chromaIds), e.getMessage());
        }
    }
}
```

#### 14.2.2 CatalogController 代码设计 `[P2]`

```java
/**
 * 知识目录 REST 控制器。
 * <p>
 * 提供知识目录树查询和统计概览两个只读端点。
 * 目录树由 KnowledgeCatalogService 基于数据源配置实时构建，
 * 无需持久化存储；监听 ETL 完成事件以保证索引时效性。
 * </p>
 * <p>
 * 权限：P2 阶段所有已认证用户均可浏览知识目录，
 * 不在此层做 ABAC 细粒度域过滤（目录树展示的是全貌，检索阶段再由 DomainRouter 做域裁剪）。
 * </p>
 *
 * @author agent-qr
 */
@RestController
@RequestMapping("/api/catalog")
@RequiredArgsConstructor
@Slf4j
public class CatalogController {

    private final KnowledgeCatalogService catalogService;

    /**
     * 获取三级知识目录树。
     * <p>
     * 返回结构：
     * <ul>
     *   <li>一级：业务域节点（DomainNode），含域名、数据源数量、实体总数</li>
     *   <li>二级：数据源节点（SourceNode），含数据源类型、最后同步时间、同步总量</li>
     *   <li>三级：实体节点（EntityNode），含实体名称、类型、记录数、最后更新时间</li>
     * </ul>
     * </p>
     *
     * @return 目录树
     */
    @GetMapping("/tree")
    public Result<CatalogTree> getCatalogTree() {
        CatalogTree tree = catalogService.getCatalogTree();
        log.debug("目录树查询完成: {} 个域", tree.getDomains().size());
        return Result.success(tree);
    }

    /**
     * 获取知识目录统计概览。
     * <p>
     * 聚合统计域数量、数据源总数和实体总数，
     * 供前端 Dashboard 或目录页概览卡片使用。
     * </p>
     *
     * @return 统计数据（totalDomains / totalSources / totalEntities）
     */
    @GetMapping("/stats")
    public Result<Map<String, Object>> getStats() {
        Map<String, Object> stats = catalogService.getStats();
        return Result.success(stats);
    }
}
```

### 14.3 Service 层设计

#### 14.3.1 KnowledgeCatalogService `[P2]`

| 方法 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `getCatalogTree` | — | `CatalogTree` | 按 domain 分组所有活跃数据源，构建三级目录树 |
| `getStats` | — | `Map<String,Object>` | 聚合 totalDomains / totalSources / totalEntities 统计 |
| `getEntitiesForSource` | `DataSourceConfig` | `List<EntityNode>` | 根据数据源类型推断实体列表（JDBC→TABLE, REST→API, S3→FILE） |
| `mapSourceTypeToEntityType` | `String` | `String` | 数据源类型到实体类型的映射 |
| `onDataETLed` | `DataETLedEvent` | `void` | 监听 ETL 完成事件，记录日志（目录索引为惰性计算） |

**`getCatalogTree()` 处理流程：**

```
1. 调用 dataSourceMapper.selectAllActive() 获取所有活跃数据源
2. 按 ds.domain 分组（null → "COMMON"），使用 LinkedHashMap 保持有序
3. 对每组域：
   a. 遍历域下的数据源，调用 getEntitiesForSource(ds) 构建实体列表
   b. 构建 SourceNode（含 sourceId/name/type/lastSyncAt/totalSynced/entities）
   c. 统计域下所有数据源的实体总数 → DomainNode.totalEntities
   d. DomainNode.sourceCount = 域下数据源数量
4. 将 DomainNode 列表封装为 CatalogTree 返回
```

**`getStats()` 处理流程：**

```
1. 调用 getCatalogTree() 获取完整目录树
2. totalDomains = domains.size()
3. totalSources = domains 中所有 SourceNode 数量之和
4. totalEntities = domains 中所有 EntityNode 数量之和
5. 封装为 Map 返回
```

#### 14.6.1 DomainRouter（关键词域路由器） `[P2]`

| 方法 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `route` | `String query` | `DomainRoutingResult` | 提取关键词 → 遍历目录树 → 计算域匹配分数 → 返回路由结果 |
| `buildRetrievalFilter` | `DomainRoutingResult` | `Map<String,String>` | 降级时返回空 Map（全库检索），否则返回 `{domain: "HR,FINANCE"}` 过滤条件 |
| `extractKeywords` | `String query` | `List<String>` | 按空格/标点分词，过滤停用词和短词（< 2 字符） |
| `isStopWord` | `String word` | `boolean` | 中英文停用词判断 |

**域路由匹配算法（设计文档 17.7 节有详细伪代码）：**

```
1. 提取查询关键词列表
2. 遍历目录树的每个域：
   a. 域名匹配：domainName 包含关键词 → score += 0.5
   b. 数据源名匹配：sourceName 包含关键词 → score += 0.3
   c. 实体名匹配：entityName 包含关键词 → score += 0.4
3. score > 0 的域加入 matchedDomains
4. 无匹配 → fallbackToGlobal=true（降级到全局检索）
5. 返回 DomainRoutingResult
```

> P3 将升级为 `DomainRouterV2`，使用 Embedding 语义相似度替代关键词包含匹配，提升路由准确性。

## 17. 关键算法说明

### 17.1 递归字符分割算法 `[P1]`

```
输入：长文本 text，目标切片大小 chunkSize=500，重叠大小 overlap=50
输出：文本片段列表

算法步骤：
1. 按 "\n\n" 将文本初步分割为段落列表
2. 遍历每个段落：
   a. 若段落长度 ≤ chunkSize：直接加入结果
   b. 若段落长度 > chunkSize：
      - 从位置 0 开始，每次取 chunkSize 长度的子串
      - 在子串末尾附近寻找断点（。\n！？；，等）
      - 下一段起始位置 = 当前断点 - overlap
      - 直到处理完整个段落
3. 合并过短片段（长度 < 100）到前一个片段
4. 返回切片列表
```

### 17.2 混合检索 + RRF 融合 + Rerank 流程 `[P2]`

```
输入：用户问题 query，查询向量 Vq
输出：精排后的 Top-K 文档片段列表

算法步骤：
1. 双路召回（并行）：
   a. 语义检索：ChromaDB.similaritySearch(Vq, topK=20) → 候选集 A
   b. 关键词检索：BM25Retriever.keywordSearch(query, topK=20) → 候选集 B

2. RRF 加权融合去重：
   对每个文档 d：
     RRF_score(d) = w1/(k+rank_A(d)) + w2/(k+rank_B(d))
     其中：w1=0.6, w2=0.4, k=60（平滑常数）
   按 RRF_score 降序排列，去重合并

3. Rerank 精排：
   对融合后的候选集，使用 bge-reranker-v2-m3 交叉编码器
   逐个计算 [query, doc_i] 的相关性分数
   按分数降序排列，取 Top-K=5

4. 组装返回结果（含 Rerank 分数、文档标题、内容片段）
```

### 17.3 死信队列指数退避重试 `[P2]`

```
输入：失败事件 event，当前重试次数 retryCount（0-based）
输出：重试调度时间

算法步骤：
1. 计算退避延迟：delay = 3^(retryCount+1) 秒
   retry 0 → 3s, retry 1 → 9s, retry 2 → 27s, retry 3 → 81s

2. 判断是否超限：
   - retryCount >= 4 → 标记 DEAD，停止重试，通知管理员
   - retryCount < 4 → 更新 nextRetryAt = now + delay

3. 定时扫描器每 30 秒拉取 nextRetryAt ≤ now 的记录执行重试
```

### 17.4 LLM 熔断器状态机 `[P2]`

```
状态转换规则：
  CLOSED ──(连续失败 ≥ 3 次)──→ OPEN
  OPEN   ──(30 秒超时)───────→ HALF_OPEN
  HALF_OPEN ──(探测成功)─────→ CLOSED
  HALF_OPEN ──(探测失败)─────→ OPEN

降级策略：
  OPEN 期间 → 自动使用 DeepSeek API 备用链路
  对用户完全透明，无感知切换
```

### 17.5 字符集自动检测与转码 `[P2]`

```
输入：原始文本字节流 bytes
输出：UTF-8 编码的文本字符串

算法步骤：
1. 使用 juniversalchardet 库检测字节流编码：
   UniversalDetector.detectCharset(bytes) → detectedCharset
2. 置信度评估：
   - 置信度 ≥ 0.8 → 使用检测到的编码解码
   - 置信度 < 0.8 → 回退尝试常见编码序列：
     [UTF-8, GBK, GB2312, ISO-8859-1, Windows-1252]
3. 解码成功 → 转码为 UTF-8
4. 解码失败 → 标记为编码异常，写入质检报告
```

### 17.6 结构化数据 → 自然语言转换算法 `[P2]`

```
输入：结构化行记录 {field1:value1, field2:value2, ...} + 字段映射配置
输出：语义完整的自然语言段落

算法步骤：
1. 获取表/实体注释作为段落标题：
   title = metadata.table_comment || "数据记录"

2. 按字段优先级（priority）排序，逐字段生成文本：
   对每个字段 field：
   a. 检查值是否为空 → 空值跳过
   b. 应用字典翻译：
      displayValue = dictMapping[rawValue] || rawValue
      （如 "D01" → "研发部"）
   c. 应用格式转换：
      - DATE_TO_CHINESE: "2024-01-15" → "2024年1月15日"
      - MONEY_FORMAT: "15000.00" → "15,000"
      - PERCENTAGE: "0.85" → "85.0%"
   d. 应用自然语言模板：
      template = "{字段中文名}为{值}{单位}"
      text = template.replace(值, displayValue).replace(单位, unit)

3. 将所有字段文本用"，"连接，末尾加"。"
4. 返回完整段落
```

### 17.7 知识目录检索路由算法 `[P2 关键词 + P3 语义]`

```
输入：用户问题 query，知识目录树 catalog
输出：DomainRoutingResult（匹配域+权重+过滤条件）

算法步骤：
1. NLP 分词提取关键实体词：
   keywords = IKAnalyzer.tokenize(query)
   过滤停用词，保留名词和专有名词

2. 遍历目录树计算域匹配分数：
   对每个业务域 domain：
     score = 0.0
     a. 域名匹配：domain.name 与 query 的 TF-IDF 相似度 × 0.5
     b. 数据源匹配：每个 source.name 匹配得分 × 0.3
     c. 实体匹配：每个 entity.name 匹配得分 × 0.4
     若 score > 0，加入 matchedDomains

3. 路由决策：
   - matchedDomains 非空 → 构建 metadata filter，裁剪检索范围
   - matchedDomains 为空 → fallbackToGlobal=true，全库盲搜

4. 构建 ChromaDB filter：
   filter = { "domain": "HR,FINANCE" }
   语义检索 + BM25 仅在 filter 范围内的切片中检索
```

### 17.8 批量向量化攒批算法 `[P2]`

```
输入：切片流（无界），批量大小 B=32，超时 T=100ms
输出：批量 Embedding 向量

算法步骤：
1. 启动 N 个消费者线程（N = CPU 核心数），每个线程维护一个本地批次列表
2. 生产者线程将 ChunkEmbedTask 放入 BlockingQueue
3. 每个消费者循环执行：
   a. 从 BlockingQueue.poll(T, MILLISECONDS) 取任务
   b. 任务放入本地批次列表
   c. 触发条件：批次.size() >= B OR poll 超时
   d. 触发时：调用 embedBatch(texts) 一次处理整批
      → 成功：分发向量到各 CompletableFuture
      → 失败：整批失败（批次 07 · 任务 7.2.5 设计变更，原为"降级为逐条 embed() 重试"）
         整批 future 以 completeExceptionally 结束，不做逐条重试
         —— 逐条重试在服务整体不可用时只是把同样的失败调用再做 N 次，
            既无收益又会刷出 N 条重复错误日志；
            数量不一致（真批量端点部分失败/截断）同样整批失败，杜绝按索引错配
   e. 清空批次，重置超时计时器

时间复杂度：O(N/B) 次 API 调用 vs O(N) 次逐条调用
空间复杂度：O(B) 攒批缓存 + O(N) 结果 CompletableFuture
性能收益：50 万切片从 27 小时 → 16 分钟（100 倍）
```
